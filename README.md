# Olympic Protocol · 校园通行指挥台

把**课表、语音播报、定位、路线规划**串成一件事：不用自己记时间，
页面会告诉你下一节课在哪、要走多远、几点必须出发，并在该走的时候开口提醒。

纯静态页面，无框架、无外部依赖、无构建步骤，也不需要任何 API key。

## 快速开始

双击 `index.html` 就能看界面，但**定位功能需要走本地服务**（浏览器只在 https 和
localhost 下允许获取位置）：

```bash
node tools/serve.js          # 然后打开 http://localhost:5173
```

想先跑一遍计算逻辑的自检：

```bash
node tools/selftest.js             # 1091 项检查，不联网
node tools/places-live.js          # 联网实测一次地图取点（默认查港中文一带）
```

#### 修一个发丝线的手机端排版错误（2026-10-01）

主卡那行读数（距离 / 步行 / 爬升 / 建议出发）原来是
`repeat(auto-fit, minmax(88px, 1fr))`——**让浏览器自己决定排几列**。
而分隔线的规则是"每格一条左竖线、只豁免第一格"，这套规则只在"单行"时成立。

实测三档手机宽度，浏览器都只排成 2 列（320 → 2×107.5、375 → 2×135、
414 → 2×154.5），于是第二行开头那格变成行首却**没被豁免**，屏幕上会出现
一条条游离的竖线，而且行与行之间没有横线。

改法：

- **列数显式写死**：3 格 3 列、4 格 4 列（格数由脚本写在 `data-cells` 上），
  宽屏永远是一整行；
- **窄屏（≤620px）单独一套规则**：两列排，竖线只留在"行内第二格"，
  行与行之间补横线——这套对 3 格和 4 格都成立；
- 宽屏既然不换行，就不给第 4 格加多余的横线。

自检里钉了四条，其中一条是认"声明本身有没有 auto-fit"，不是认注释里提到的词
（写这条断言时被自己的注释坑过一次）。

**第二轮（同一天，用户反馈"依旧很诡异"）**：上面那条只修了一半。真正的原因有两条：

1. **「爬升」那格没数据时是 `hidden`，但它仍然是 DOM 里的兄弟节点**——
   于是"最后一个可见格"的奇偶位整体错开，靠 `:nth-child(odd/even)` 判断行首/行尾
   全都不准。现在两套排法按 `data-cells` 分开写（4 格 → 完整 2×2；3 格 →
   第一行两格 + 最后那格横跨整行），条件都是确定的，不看奇偶。
2. **还有一条旧的窄屏规则在打架**：`@media (max-width: 430px)` 里留着发丝线改造
   之前的 `.hero-stats { 1fr 1fr }` + `.hero-stats .stat:last-child { grid-column: 1 / -1 }`，
   它会把 4 格时的最后一格也拉成整行——于是手机上看到"半格空着、横线只画一半"。
   两条旧规则已删掉，并加了断言：跨列规则要指名道姓地限定（当时只允许出现在
   `data-cells="3"` 里；这条断言在下面的第三轮又扩了一次）。

实测数字（375px）：3 格 → 2 列 + 末格跨整行；4 格 → 2 列、末格不跨列、左线 1px、上线 1px；
720px → 4 列一整行、末格上线 0px。

**第三轮（同一天，用户："手机端定位 UI 发丝线分格显得很拥挤，尝试使用两行"）**：

出问题的不是今日主卡，是设置页「定位」卡片下面那张读数行——三格是
**当前坐标 / 精度 / 最近楼栋**。坐标是 `22.41830, 114.20520` 这样一串长文本，
手机上塞进 1/3 宽的一格里会被硬折成三四行，那一格比旁边两格高出一截，
发丝线就跟着"挤"起来。

改法：给那张读数行加一个 `stats-lead-wide` 标记，在同一个 `@media (max-width: 620px)`
里改成两行排——**坐标独占第一行**（`grid-column: 1 / -1`），
**精度和最近楼栋并排第二行**（行首那格不画竖线，第二行起补横线）。
宽屏一个声明没动，还是三格一整行。

实测（还是那套固定宽度 iframe 的量法，读 `getComputedStyle` 不靠看截图）：

| 宽度 | 网格列 | 当前坐标 | 精度 | 最近楼栋 |
| --- | --- | --- | --- | --- |
| 320px | 2 × 115.5px | 跨整行 231×63 | 上线 1px / 左线 0 | 上线 1px / 左线 1px |
| 375px | 2 × 143px | 跨整行 286×63 | 上线 1px / 左线 0 | 上线 1px / 左线 1px |
| 720px | 3 × 210.3px | 常格 210×63 | 上线 0 / 左线 1px | 上线 0 / 左线 1px |

跨列规则的断言也跟着改成"全表只允许两条，各被 `data-cells="3"` / `stats-lead-wide`
限定"——以后谁再加一条"无条件跨列"的规则，自检会直接红。

**接着又补了一刀（同一天，用户："自动换行后，第二行左侧不应出现发丝线"）**：

第一刀只把"列"排对了，没管"线"。竖线是**行内两格之间**的分隔符，所以只要某格
落在新一行的行首（贴着卡片左边缘），它就一条竖线都不该有——否则那条线孤零零
浮在卡片左边，就是"鬼线"。窄屏两列排布下，行首一共只有四种情况：

| 情况 | 行首那格 | 处理 |
| --- | --- | --- |
| 3 格 | 第二行「建议出发」（跨整行） | `[data-cells="3"] .stat:last-child` |
| **4 格** | **第二行「爬升」（第 3 个兄弟）** | **`[data-cells="4"] .stat:nth-child(3)` ← 这次补的** |
| 定位卡片 | 第一行「当前坐标」（跨整行） | `.stats-lead-wide .stat:first-child` |
| 定位卡片 | 第二行「精度」 | `.stats-lead-wide .stat:nth-child(2)` |

真凶就是 4 格那一行：基础规则 `.stat { border-left: 1px }` 给**每一格**都画线，
只豁免了第 1 个兄弟；4 格第二行的行首是第 3 个兄弟，于是多出一条线。
实测（320 / 375 / 414 三档，强制成 4 格）：改前第 3 格 `border-left=1px`，
改后 `0px`，而同一行右边那格（建议出发）仍然是 `1px`（竖线该留的还得留）。

这次加了两条断言，而且**验证过它们不是摆设**：把 `border-left: 0` 临时改回
`1px`，自检立刻红两条，报的正是"4 格第二行（爬升）"。

顺带记一个量法上的坑：驱动页里用 flex 并排三个固定宽 iframe 时，
**必须写 `flex: none`**，否则 flex 会按容器宽度把它们等比压窄，
三个档位量出来是同一个数（第一次就踩了这个坑，320/375/720 全报 211px）。

视频的来历：原片是一支 4 分钟的 mv（2560×1440、60fps、带音轨，495MB），
但**画面本身就是 16 秒一循环**。逐帧比对确认过：第 960 帧（60fps 下的第 16.000 秒）
与第 0 帧的平均像素差只有 0.47，而前后相邻帧是 1.5～2.1，再往后就一路涨到 13——
也就是说 16.000 秒正好是一个完整循环。于是只截前 16 秒、去掉音轨、缩到 1280×720/30fps，
压成 1.8MB 的 `bg-loop.mp4`；截断处正好落在循环点上，接起来看不出接缝。

几处兜底：

- 视频底下垫着原来那张静态图 `voaf_ga09.jpg`（也是 `poster`），视频没播起来时不会是白板；
- 有些浏览器（iOS Safari、以及「加到主屏」后的独立窗口）不认 `autoplay`，
  脚本会主动补播一次，再不行就等用户第一次点屏幕时补；
- 系统开了「减少动态效果」就不放视频了，退回那张静态图（也不再偷偷播，省电）。

界面本身也做成半透明的，不然再好看的背景也被挡住：卡片 0.55 的白、次级面（按钮、
下拉框、输入框）0.46、顶栏和底部导航 0.66～0.68，最上面那层粉色纱从 0.62/0.72 调薄到
0.40/0.50。两个配套动作：

- 卡片加了 `backdrop-filter: blur(12px)`——视频一直在动，不模糊的话字会跟着飘；
- **确认框（`modal-card`）反而做得更实**（0.9），那是要人做决定的地方，看得清才敢点确定。

再提醒一句改这个的坑：卡片的渐变是 `linear-gradient(180deg, var(--card), var(--bg-soft))`，
`--bg-soft` 原来是个实色 `#ffe8f2`，光把 `--card` 调透没用，**下半截还是实心的**。
现在 `--bg-soft` 也是 rgba，自检里专门有两条盯着这个（半透明 + 不带实色 stop）。
另外街道图 / 港中文图那两种真实底图保持不透明，地图透了就没法看了。

### 提示条（点了「播报」之后弹出来那条）

这条之前是**深蓝底**——旧暗色主题留下来的，而字色是从 body 继承的深褐，
深字配深底，对比度只有 **1.36:1**（正常文字要求 4.5:1），基本等于看不见。

现在改成粉白毛玻璃条 + 左侧一条语气色，字全是深色：

| | 颜色 | 对白底的对比度 |
|---|---|---|
| 底色 | `rgba(255,255,255,.97)` + 模糊 | —— |
| 正文 | `--text #4a2b3a` | **11.6:1** |
| 标题（默认） | `--accent-ink #c9256c` | 4.96:1 |
| 标题（完成） | `--ok-ink #177a4f` | 5.00:1 |
| 标题（提醒） | `--warn-ink #9a5a00` | 5.13:1 |
| 标题（出错） | `--err-ink #c62236` | 5.34:1 |

这里有个容易踩的点：**点缀色不能直接当文字色**。`--accent #ff5fa2` 当文字用
只有 **2.65:1**，`--ok #2fae76` 也只有 2.8:1 左右——它们适合做边框、圆点、进度条，
写字就得用上面那组 `*-ink` 加深色。自检里这一组是**把对比度算出来**验的
（按 WCAG 的相对亮度公式，半透明底色按压在最暗的背景下折算），不是"看着差不多"。

语气只靠左侧竖线和标题色区分，**底色统一**——绿底黄底跟粉色主题放一起会打架。

两条实现细节，都是为了不被系统设置坑到：

- `color-scheme: light` —— 不然系统开深色模式时，滚动条、滑块、日期选择器
  这些**原生控件还是黑的**，在浅色底上很扎眼；
- 滑块（语速/音量）自己重画过，不再依赖浏览器默认样式。

另外支持系统的「减少动态效果」：开了就把所有动画关掉（对晕动症用户友好）。

### 连堂课不会拆成两段

两节课在同一栋楼、中间只隔十几分钟是常事。这种情况**只出一段行程**，
不会再拆出一段"从这栋楼去这栋楼"——距离是 0，校巴方案也会变成原地打转，
看着像坏了。

### 简图上画什么

地图卡片右上角可以切换**三种底图**：

| 底图 | 说明 |
|---|---|
| **简图**（默认） | 纯 SVG，按经纬度等比投影。不联网、不依赖任何外部资源 |
| **街道图** | OpenStreetMap，开放数据，任何人都能自由使用 |
| **港中文** | 香港中文大学自己的校园地图瓦片 |

选择会记住。**默认用简图**是因为它是唯一离线可用的、也不依赖任何第三方服务；
选真实地图时才按需下载 Leaflet（约 150 KB），不选就不下载。

> **关于港中文那张地图**：它是学校自己的地图资源，不是开放数据。
> 自己用没问题，但这个页面是公开站点，要给很多人用之前建议先问一下学校。
>
> 另外说明一下为什么不是直接用学校官网那个地图：它用的是 Google Maps +
> 学校自己的 API key，那个 key 有域名限制，而且拿别人的私钥给自己的应用用也不合适。
> 所以这里是照着它的瓦片地址（`/english/images/campus/tile-map/{z}/{x}/{y}.png`）
> 自己搭的图层，用的是 Leaflet。

导入一次地图可能带回上百栋楼，全画上去今天要去的反而找不着。
所以**只画今天用得上的三类，其余楼栋一概不画**：

| 图上的样子 | 含义 |
|---|---|
| 青色脉冲圆点，标「我的位置」 | 你当前的位置 |
| 实心圆 + **「下一节」旗标** | 下一节课所在的那栋楼 |
| 空心圆 + **编号 + 楼名 + 上课时间** | 今天所有课室楼栋，按上课先后编号 |
| 虚线 + 段距 | 当前位置 → 第一节 → 第二节…的行程链 |

**两套地图的标记大小是反着来的**，因为它们要解决的问题相反：

| | 我的位置 | 下一节 | 其余 | 楼名字号 |
|---|---|---|---|---|
| 简图（SVG） | 10 | 18 | 15 | 17（简写） |
| 街道图 / 港中文图 | 5 | 24px 的圆点 | 24px 的圆点 | 11px |

简图是"一眼看清今天去哪几栋"，底图是空的，所以要大；真实底图信息本来就密，
点大了就盖住路和楼名，所以要小。

### 简图上的地名怎么画

一堆全称挤在简图上会糊成一片，所以简图上的地名做了三件事：

1. **去掉通用词**：`Academic Building No.2` → `Academic No.2`、
   `Esther Lee Building` → `Esther Lee`、`Lady Shaw Building C3` → `Lady Shaw C3`。
   去掉的是 Building / Centre / Complex / Block / Tower 这一类**只说明"这是个楼"的词**，
   名字本身原样留着。两个边界：去完只剩一个词就不去（`Science Centre` 不能变成
   `Science`）；整体还是太长（超过 26 字）才按整词截断。
   本来就短的 `12W`、`C3`、`LT2` 原样不动，中文名给到 8 个字。
   **全称没丢**：每块字都带 `<title>`，鼠标停上去 / 手机上长按还能看到完整名字，
   下面的行程列表里也一直写着全称。

   > 一开始做成了取首字母拼代号（`Academic Building No.2` → `AB2`），
   > 用户反馈太激进——简图上认不出是哪栋。**简写只要去掉"楼"这类词就够了**。
2. **字小一号、加透明度**：楼名 17px、透明度 0.72；时间 13px / 0.6；
   校巴站名 12px / 0.68。地名是底衬，不该比圆点和路线还抢眼。
   **但圆里的编号、「下一节」旗标、「我的位置」保持不透明**——那几个是要看清的。
3. **放在上面还是下面，按"谁少压住谁"来选**：每块字先试放下面，跟已经排好的字
   （或别的圆点）压住了就翻到上面。排的先后是：课程楼栋 → 「下一节」和「我的位置」
   → 校巴站；校巴站最密，让它先让步。挤出画面的方案会被重罚，宁可压着字也不出图。

> 这三条是后改的。原来简图上的字是"越大越清楚"（楼名 24px、强制不透明），
> 楼一多反而全糊在一起。现在自检里是**反着**验的：
> 楼名必须 ≤ 17px 且半透明、「我的位置」和旗标必须还是不透明、
> 简写规则逐条对比、以及**真的跑一次渲染**看两块挨着的字有没有分到上下两侧。

> 真实地图上**只有「下一节」那栋常驻显示标签**，其余鼠标悬停或点一下看。
> 几栋楼挨在一起时全部常驻会叠成一团，反而什么都看不清。

> 又踩了三个坑，都记在这里：
> 1. **`.map-wrap svg` 是后代选择器**，本意只想管简图那个 SVG，结果把 Leaflet
>    版权栏里内置的那面国旗 SVG 也一起套上了 `width: 100%`，
>    渲染成一个巨大的蓝黄色块。改成 `#mapSvg` 只作用于简图本身。
> 2. **SVG 元素没有 `hidden` 这个 DOM 属性**，写 `svg.hidden = true`
>    只是挂了个没用的变量，属性根本不会设上，于是隐藏的简图仍然占着布局空间。
>    改成直接控制 `style.display`。
> 3. **Leaflet 的 z-index 会跑出地图**。它内部把图层面板设成 400、控件 1000，
>    而地图容器自己没有层叠上下文时，这些值直接拿去跟整页比高低——
>    路线页往下滑，地图就盖住了顶栏「Olympic Protocol」和底部导航。
>    给 `.map-wrap` 加 `position: relative + z-index: 0 + isolation: isolate`
>    建一个层叠上下文，Leaflet 的层级就只在自己这块地盘里算。
>    实测过：把那三条临时去掉，顶栏立刻被瓦片盖住；加回来就正常。

几个细节：

- **同一栋楼去了两次会合并**，时间都列出来，例如「第一教学楼 08:00 · 14:00」
- **取景范围只按今天要去的楼 + 你的位置来算**，所以画面会自然放大到有用的那块，
  而不是被上百栋楼撑开
- 图上标的距离和下方行程列表**用的是同一套折算方式**，数字对得上
- 还没定位时图上会写「打开定位后会显示你的位置」，免得以为坏了
- 所有文字都加了描边光晕——楼名、时间、距离经常挨得很近，没有光晕会糊成一团

**课表** — 全部课程按星期分组，可以增删改，支持 JSON 导入导出。

**设置** — 定位状态、语音音色与语速、提醒提前量、步行参数、学期开始日期。

> **「从地图读取附近楼栋」和「校区楼栋」两张卡片默认藏起来了**（日常用不到，
> 楼栋数据已经内置好）。要重新打开：把 `index.html` 里那两处 `hidden` 属性去掉，
> 或者把 `js/app.js` 里的 `SHOW_BUILDING_TOOLS` 改成 `true`。
> **代码和 DOM 全都留着**——补坐标、从 OSM 搜楼、改别名、拉海拔仍然照旧能用，
> 只是默认不显示。以前那句「去设置 → 校区楼栋补一下」的提示，
> 在卡片藏起来的时候得先按上面的办法打开才能照做。

楼栋多了以后（从地图导入一次可能就上百栋），列表上面有**搜索框**：

- 关键词**同时匹配名字和别名**，而且和宿舍搜索共用同一条规则：

- 旁边有「**只看还没坐标的**」开关——从课表截图导入时新建的楼栋会没有坐标，
  用它可以一次揪出来集中补
- 两种条件可以叠加，比如「名字带 Lee」+「只看缺坐标」

全部是**本地筛选，不联网**，边打边出。列表上方会显示「共 138 栋，其中 5 栋还没坐标 ·
当前显示 3 栋」这样的数量，不会让你以为是列表坏了。

> **两个筛选条件是叠加的。** 搜「lady shaw」明明有这栋楼却什么都不显示，
> 最常见的原因是上面那个「只看还没坐标的」还勾着——有坐标的楼会被它滤掉。
> 所以现在遇到这种情况会直接说明：
>
> > 有 1 栋符合「lady shaw」，但被「只看还没坐标的」筛掉了 —— 取消勾选就能看到
>
> 开启那个开关时，列表上方的计数也会写明「「只看还没坐标的」已开启」。

### 排列顺序

楼栋统一**按名字排序**：英文按字母，中文按拼音，数字按大小
（`Building 2` 排在 `Building 10` 前面，而不是按字符逐位比），大小写不参与比较。

排序在三个地方生效，所以列表、下拉框、导出文件的顺序永远一致：
从本地读取时排一次、每次保存前再排一次。

在同一个排序函数里用了 `localeCompare` 配合 `"zh-Hans"`，
所以中英混排也不会出现"英文全在前面、中文全在后面"这种奇怪结果。

## 从地图读取附近楼栋

设置 → 从地图读取附近楼栋：站定位置，点「搜索附近建筑」，页面会列出半径内的
带名建筑，勾选后一键加进楼栋列表，不用手抄经纬度。

数据来自 **OpenStreetMap**，通过 Overpass API 查询。选它的原因：

- **免费、免密钥、免注册**，不用申请账号，也不会产生任何费用
- **国内可以直接访问，不需要代理**。Overpass 接口本身允许浏览器跨域调用，
  所以纯静态页面（包括线上那一版）也能正常用
- 坐标是标准 WGS-84，和手机 GPS 完全一致，不需要任何坐标转换
- 实测清华园 800 米内能查到 142 栋带名建筑

代价是数据由志愿者录入，**校园建筑覆盖因学校而异**。大一点的校园通常够用，
但小学校可能只有零星几栋楼，甚至一栋都没有。真遇到那种情况，就站在楼门口用
「用我的当前位置填入」手工录，其实也就几秒钟的事。

### 关于高德和 Google

代码里现在**只保留 OpenStreetMap 这一个来源**，之前接的高德和 Google 已经移除：

- 高德接口不返回跨域头，浏览器直连会被拦，必须额外搭一个转发服务才可用；
  线上是纯静态托管，没有这个条件
- Google 的 `maps.googleapis.com` 在大陆网络不通，Places API 还要绑定 Cloud
  结算账号，而且 Google 在中国境内的单体楼栋数据非常薄
- 高德返回的是**楼内 POI 而不是楼栋**，同一栋楼里会有十几个坐标完全重合的
  「某实验室」「某报告厅」，还得再做一轮合并才能用

如果以后想加回来，`js/places.js` 里现在只剩 Overpass 一条路径，
重新接的话需要把请求构造和结果解析都写一遍。

### 合并功能

搜索默认开着 **「合并同一栋楼内的地点」**：把 25 米内的点位并成一个，
挑一个名字当代表。OpenStreetMap 里同一栋楼有时既有中文名又有英文名，
或者被拆成几个入口点，不合并的话列表里会出现好几个几乎一样的位置。

被合并掉的名字不会丢，会在条目下方列出来，方便你判断这是哪栋楼。
嫌合并得太狠或者太松，把阈值改一下就行（`js/places.js` 里的 `cluster`，默认 25 米）。

### 导入课表后自动补齐楼栋

导入课表时，匹配不上已有楼栋的地点会先建一个**没有坐标的占位**。
以前要一栋栋手工去搜、去补，现在**导入完会自动跑一遍**：

1. 找出所有还没坐标的楼栋
2. 逐个拿名字去 OSM 找（走名字检索，不是半径搜索）
3. **模糊匹配挑最像的那一栋**：`Lady Shaw Bldg` 对得上 `Lady Shaw Building`，
   `Yasumoto Int'l Acad Park` 对得上 `Yasumoto International Academic Park`
4. 把坐标填进去，并把 OSM 上的中英文名补成别名

显示名保留课表里的写法不变，OSM 的名字只进别名——这样以后中英文写法都能匹配。
补不上的（比如地点写的是"待定"、名字打错）会列在提示里，不会悄悄跳过。

设置 → 校区楼栋 → **「自动补齐」** 也可以随时手动跑一次。

> 实测效果：
>
> | 课表里的写法 | 结果 |
> |---|---|
> | `Lady Shaw Bldg` | ✅ 补上坐标，别名「邵逸夫夫人樓、Lady Shaw Building」 |
> | `Yasumoto Int'l Acad Park` | ✅ 补上坐标，别名「康本國際學術園、Yasumoto International Academic Park」 |
> | `Some Totally Made Up Building` | ⏭ 跳过（OSM 里确实没有） |
>
> **两个坑**：一是缩写直接拿去检索搜不到（实测 `Yasumoto Int'l Acad Park`
> 返回 0 条，展开成全称才有），所以检索前会先把常见缩写展开；
> 二是 Nominatim 的使用条款要求每秒最多一次请求，所以是**逐个串行 + 间隔 1.1 秒**，
> 楼栋多的时候会慢一些，按钮上会显示进度。

「从地图读取附近楼栋」有两种搜法，解决的问题不一样：

| 搜法 | 用途 | 走什么 |
|---|---|---|
| **搜索附近建筑** | 看看周围有什么 | Overpass 半径查询 |
| **按名字搜** | 找某一栋具体的楼 | OSM 官方地名检索（Nominatim） |

**为什么必须分两种**：半径查询有结果条数上限（800 米约 150 条），
而校园里带名字的建筑动辄上百栋。更麻烦的是 **Overpass 不按距离排序**，
截掉哪些是不确定的——搜「Lady Shaw」搜不到就是这个原因，它没进那 150 条。

所以想找指定的楼，用**按名字搜**：输入 `Lady Shaw` 或 `邵逸夫` 都能找到，
和半径无关。半径搜索结果顶到上限时页面也会提醒你改用这个。

> 名字搜索有个坑：**Nominatim 按请求方的语言偏好只返回单一名字**，
> 浏览器默认要中文，于是拿到的是「邵逸夫夫人樓」——没有英文，
> 导入后匹配不上英文课表。
>
> 所以拿到结果后**会再用 OSM 的元素接口取一次原始标签**，
> 那里 `name` / `name:en` / `name:zh` 都在，中英文名就都齐了：
>
> > Lady Shaw Building 「教学楼」 又名：邵逸夫夫人樓

Overpass 的公共节点是免费共享的，**快慢完全取决于对方当时的负载**，这一点绕不过去。
实测同一个查询：顺利时 1.7 秒返回，节点繁忙时直接不响应。

能做的是不让"对方慢"变成"你等更久"。之前有个自找的坑：节点失败后会串行换下一个，
而备用节点实测要 45 秒才超时，于是最坏情况变成**两次超时叠加的 40 秒**。

现在的做法：

| 措施 | 效果 |
|---|---|
| **对冲请求** | 主节点迟迟没动静就并行发一份给备用节点，谁先回来用谁，先到的自动取消另一个 |
| **超时跟着半径走** | 见下一节，800 米以内 30 秒，3 公里放宽到 74 秒 |
| **结果缓存 5 分钟** | 同一位置重复搜索瞬间返回 |
| **开关不再联网** | 合并、优先英文名、名称过滤都是纯本地重算，以前每次都重新联网，白等好几秒 |
| **显示已用秒数** | 搜索时状态栏会走秒，不会看起来像卡死 |

另外**把搜索半径调小会明显变快**——服务器要处理的数据少了一大截。
800 米能覆盖整个港中文本部，如果只关心某几栋楼，调到 400–500 米就够。

### 搜大范围时超时会自动放宽

半径越大，服务器要扫的建筑越多，返回的数据量也越大。如果超时是固定的，
大范围搜索几乎必定失败。实测：

| 半径 | 耗时 | 返回条数 |
|---|---|---|
| 800 米 | 3.3 秒 | 138 栋 |
| 3000 米 | **18.1 秒** | **378 栋** |

3000 米那次要 18 秒——**按原来固定的 15 秒超时，它会被判定为失败**；
而且返回 378 栋，原来的 150 条上限会把它截掉一半多。

所以现在两项都跟着半径走：

| 半径 | 超时 | 结果条数上限 |
|---|---|---|
| 800 米 | 30 秒 | 150 |
| 1000 米 | 34 秒 | 188 |
| 1500 米 | 44 秒 | 281 |
| 2000 米 | 54 秒 | 375 |
| 3000 米 | 74 秒 | 400 |
| 5000 米 | 114 秒 | 400 |
| 上限 | 180 秒 | 400 |

搜索时状态栏会显示「搜索中… 8 秒（最多等 41 秒）」，这样等待是有预期的，
不会觉得卡死。半径上限从 3000 米放宽到了 5000 米。

**公共节点忙起来等几十秒是常事**，所以宽限给得比较足；等超过 30 秒时状态栏会
补一句「地图服务繁忙，请再等等」，免得看起来像卡死。服务端自己的超时上限
也同步放宽到 180 秒，不然会出现"客户端还在等、服务端先掐断"的矛盾。

即便如此，**拿到的名字仍然建议手工过一遍**——地图上的正式楼名和你平时叫的
可能不一样，而语音播报和路线提示读的是你设的名字。

### 中文名和英文名同时读取

OpenStreetMap 上一栋楼常常同时挂着好几个名字标记。以港中文为例，实际数据长这样：

```
name    = 科學館東座 Science Centre East Block
name:zh = 科學館東座
name:en = Science Centre East Block
```

**这三个名字会全部读进来**：一个当显示名，其余全部存成别名。默认**优先用英文名**
当显示名（课表上一般写英文），中文进别名；卡片里的开关可以反过来。

这样带来的好处是**课表和地图能对上**：

- 课表 OCR 读出 `Pi Ch'iu Building` → 靠别名精确匹配到「碧秋樓」
- 读出 `Science Centre` → 靠模糊匹配找到「Science Centre East Block」
- 中文课表读出「碧秋樓」→ 同样能匹配到同一个楼栋
- 读出缩写 `Basic Med Sci Bldg` → 匹配到
  「Choh-Ming Li Basic Medical Sciences Building 李卓敏基本醫學大樓」

最后那条靠两层规则合起来才成：先有一张常见缩写展开表
（`Bldg → Building`、`Int'l → International`、`Med → Medical`、`Sci → Science`…），
再对剩下的词做**前缀比对**——`Med`／`Medical`、`Science`／`Sciences` 算同一个词
（前缀至少要 3 个字母，否则 `Li` 会和 `Library` 拼到一起）。

光靠"词重合比例"是不够的：目标名字越长，比例被拉得越低，`Basic Med Sci Bldg`
只能拿 0.46 分，卡在阈值下面。所以再加一条——**短的那边要是几乎被全覆盖
（≥ 80%）而且至少对上了两个词，就按覆盖度给分**。这样一来既认得出缩写，
又不会因为单独一个 `Building` 就乱认一栋楼。

顺带一提，名字是**多对多**用的：筛选（搜索框）、去重（已录过的不再重复导入）、
以及课表导入时的楼栋匹配，三个地方中文名和英文名都会参与。

### 已经导入过中文名怎么办

如果之前导入的楼栋只有中文名，搜索之后那些楼栋会被标记成「已在列表」。
**直接点它下面的「把这些名字补进已有楼栋」**，英文名就会补进别名里，
课表里的英文名立刻就能匹配上——不用删掉重导，坐标也不会丢。

补名字只会往别名里加，**不会改掉楼栋的显示名**，所以界面上看到的名字不变。

### 课表地名怎么和地图地名对上

课表上的写法和地图上的正式名很少一字不差，所以匹配用的是**模糊匹配**，
分四档判断，从最可靠的一档往下试：

| 判断 | 例子 |
|---|---|
| 完全相同 | `碧秋樓` = `碧秋樓` |
| 一方包含另一方 | `Science Centre` → `Science Centre East Block` |
| 英文词重合 | 缩写会先展开，`Bldg` = `Building`、`Int'l` = `International`、`Acad` = `Academic` |
| 缩写点号并排 | `Y.C. Liang Hall` = `YC. Liang Hall`（连着的单字母并成一个词） |
| 一个字母之差 | `liang` = `liana`、`building` = `bullding`（只给 5 个字母以上的词开口子） |
| 缩写错一个字母 | `V.C. Liang Hall` = `Y.C. Liang Hall`（`Y`↔`V` 是最常见的混淆，见下） |
| 整串拼写近似 | 上面都不中时，按编辑距离再兜一次底 |

所以这些都能自动对上：

```
课表写的                        →  地图上的
Yasumoto Int'l Acad Park        →  Yasumoto International Academic Park
Lady Shaw Bldg                  →  Lady Shaw Building
Science Centre                  →  Science Centre East Block
Pi Ch'iu Building               →  碧秋樓（英文别名）
YC. Liana Hall                  →  Y.C. Liang Hall
```

最后那条是 OCR 的典型错法：**liang 被认成 liana**，只差一个字母；
再加上课表把 `Y.C.` 印成 `YC.`（点号位置也不一样），两边就彻底对不上了。
改之前它连前五名都进不去——最像的反而是随便一栋 `……Hall`（48%），
因为"英文词重合"那一档是按 jaccard 算的，**候选名字越长越吃亏**，
只剩一个 hall 能对上的短名字反而占了便宜。现在两处都修了：

- 连着的单字母先并成一个词（`y` + `c` → `yc`），所以带点号的缩写怎么印都能对上；
  只并**字母**不并数字，孤零零的单字母也不并（`Building A` 里的 A 保持原样）。
- 逐词比对时允许**一个字母之差**，但只给 5 个字母以上的词开口子，
  而且长度差只允许 1：`liang` / `liana` ✓，`hall` / `hill` ✗（4 个字母差一个就是两栋楼），
  `centre` / `centenary` ✗（长度差 3）。

   > **缩写组是例外，单独放一条口子**（2026-10-03 补）：缩写只有两个字母，
     上面"5 个字母以上"的门槛够不着，于是 `Y.C. Liang Hall` 被 OCR 读成
     `V.C. Liang Hall` 就整条匹配不上（用户报的正是这个）。现在**缩写组之间**也允许
     一个字母之差，另外把"本来就写在一起的全辅音短词"（`VC`、`LSK`、`SH` 这种）
     也算成缩写组——普通单词都带元音（`hall` / `shaw` / `ho`），不会被卷进来，
     `hall` / `hill` 那条底线照旧。
     放宽之后量过：**楼栋之间的交叉误匹配还是 92 对，一对没多**（拿部署中的旧版同数据比过）。

这条规则的边界是靠自检守住的：默认楼栋**每一个名字和别名（151 栋、336 个形式）
都必须匹配回它自己**，`TBA` / `no room required` / `待定` 这种句子一个都不许匹配上。
有了这张网，以后再调模糊匹配就不用怕"修好一个、挤歪一片"。

**匹配结果直接写在下拉框里**：命中的那栋会被选中，不是精确匹配也一样。
不是精确匹配的那几行会标黄，并写一句把握度（`自动匹配 83%`）——
只报分数，不重复念楼名（下拉框里就选着），也不再写"请确认是不是这栋"那串话。

**够像的不止一栋时，全都排在下拉框最上面**：

课表写 `Science Centre`，实际能对上的有大学科学馆、科学馆东座、科学馆北座/南座——
以前只把"最像的那一栋"放进下拉框并选中，等于把选择藏起来了，用户要选别的还得
自己从一百多栋里翻。现在分两组：

```
都够像（按把握度，选中的是第 1 个）
  University Science Centre　92%     ← 默认选中
  Science Centre East Block　85%
  Charles Kuen Kao Building　82%
  Ma Lin Building　82%
其他楼栋
  （余下 147 栋，按原顺序）
```

候选既然已经在列表里，黄字说明就只留一句把握度，不再啰嗦。
只有一个候选时保持平铺（不硬分组），跟以前一模一样。

还有个小细节：楼名后面粘着教室号时（`Science Centre L3`），
**去掉教室号再试的那一轮候选也会并进来**，但"直接那一轮的第一名"钉在最前面不动——
不然 `Building 10` 这种名字会被削成 `Building` 之后反超，挑出一栋完全不相关的楼。
把握低于 62% 的直接当匹配不上，会在导入时新建一个缺坐标的楼栋，那一条**会**提醒你补坐标。
（`YC. Liana Hall` 现在打到 85%，下一名只有 48%，分差够大，不是"勉强压线过"。）

识别结果下面那个「识别详情」是折叠的（默认收起），里面是原始文字块和分割过程，
出问题时才用得上，所以标题就写四个字。

这里有个算法解决不了的地方：`Science Centre` 在 OSM 里分成东座、西座、大学科学馆
好几个体，而课表只写 `Science Centre L3`。**L3 到底在东座还是西座，只能靠人来判断**，
所以那几条自己去下拉里挑一下。

### 课表

「课表」页从上到下是三块：

1. **全部课程**（最上面）——手动增删改，右上角两颗按钮：**新增课程** 和
   **导出课表图片**（主色那颗）。
   > JSON 的「导出 / 导入」两颗按钮按用户要求撤掉了（`Store.exportFile` /
   > `applyImport` 都还在，想恢复把按钮加回去即可）。
2. **两张左右滑动的导入卡**（跟着一张切换条）：**从学校接口拉取**（默认停在它）
   和**从截图导入**。手机上直接左右划，鼠标点上面的切换条也行。
   两张卡用的是跟路线页那三张**同一套滑动逻辑**（`makeSlides`）。

两张导入卡里都写着同一句 **「本网站不会储存您的任何个人信息」**（在 SID/密码框下面、
截图那个虚线框下面）。密码框里**不塞任何提示文字**——框内那行灰字太丑，用户要求挪到下面。
这行小字一开始给了个**负的上边距**想贴紧输入框，结果直接压到框上了（用户截图为证）；
现在老老实实用正常间距，自检里也顺手钉了"两处说明都在"。

学号/密码用标准 `autocomplete="username"` / `current-password`，**允许浏览器记住这组账号密码**
（用户要求放开；更早一版为了隐私是挡着的）。

课程字段：

```json
{
  "id": "c1",
  "name": "高等数学",
  "teacher": "张老师",
  "buildingId": "A",
  "room": "A301",
  "weekdays": [1, 3],
  "start": "08:00",
  "end": "09:40",
  "startDate": "2026-09-08",
  "endDate": "2026-12-01"
}
```

`weekdays` 用 1–7 表示周一到周日。`startDate` / `endDate` **只有从学校接口拉回来的课才有**
（上游给的就是这两个日期）；手输和截图导入的课没有这两个字段，
等于整学期都上——那两行留空即可。

#### 「适用周次」整套已经取消（2026-10）

课表里不再有 `weeks` 这个概念：

- 界面上没有"适用周次/起始教学周/结束教学周"这些输入框了；
- 别的地方（今日课表、下一节课、路线、校巴）也不再按周次筛课，
  **只看星期几**；拉回来的课额外看它自己的起止日期（免得第二学期的课在第一学期冒出来）；
- 老存档里残留的 `weeks` 会被直接忽略，不用手动清；
- **顶上那个「第 N 周」保留着**（`renderTop` 里算的），
  设置里的「学期开始日期」也保留（默认 2026-09-07）——它现在只服务于这一个显示。

课表列表里那行小字也跟着变了：拉回来的课显示 `周二 · 2026-09-08 – 2026-12-01`，
手输/截图导入的课只显示 `周二`。

**起止日期在编辑表单里也能看见、能改**（`开始日期` / `结束日期` 两个日期框，可留空）。
这是补的一个 bug：列表里本来就显示日期，但点「编辑」进去看不到，等于没法核对和修正。

### 课表导出成图片

「课表」页 →「全部课程」卡片上那颗主色的 **导出课表图片** → 弹出一张生成好的周课表 →
选比例 → **保存图片**（手机上看不清也可以长按图片保存到相册）。

**比例**有四档：自适应（就按课表内容）、**手机壁纸 9 : 19.5**、**平板竖屏 3 : 4**、
**平板横屏 4 : 3**。

**四种比例都用同一套网格**（列=星期、行=时间）——用户明确要网格。
画布尺寸是"**宽度定死、高度按比例算，再把这个高度交回排版去纵向拉长**"：

| 比例 | 效果 |
| --- | --- |
| 自适应 | 按内容（一屏就能看完的那张横版） |
| 平板横屏 4 : 3 | 网格略微拉高 |
| 平板竖屏 3 : 4 / 手机壁纸 9 : 19.5 | 网格**纵向拉长**（手机那档大约是自然高度的 4 倍） |

> 中途试过一版"竖版换成一天一段的列表"，用户否掉了：要的就是网格。
> 现在的做法更合算——**纵向拉长之后每格都够高，课室地点也能写进去**，
> 不会因为格子挤而只剩课名。

**「自适应」这一档已经撤掉了**（用户要求）——剩下的三档都要按比例铺满画布，
下拉里只剩手机壁纸 / 平板竖屏 / 平板横屏，默认手机壁纸。

**拉长有上限**（`maxPxPerMin = 2.4`，即 144px / 小时）：手机壁纸那档按画布算能拉到
220px 一小时，格子空得吓人。拉到上限之后多出来的高度就留给 `draw()` 居中——
于是手机上出来的图**上下各留一截空白**（用户要求"适当留白"），比例仍然精确。
这个数越大留白越少（2 → 各留 21%，2.4 → 各留 16%；课排满一天时约 10%）。

**上课地点一律要写**（用户要求"无论什么比例都完整显示"）。窄格子（同一时段两节课
并排时只有半列宽）用两层办法：① 把 Building / Centre 这类通用词去掉，
`Academic Building No.1 · L3` → `Academic No.1 · L3`（但至少留两个词——
`Science Centre` 被削成 `Science` 就没意义了）；② 按**最长的那个词**把字号往下收
（最小 8px），这样 `International` 这种长词也是整的，不会被断成 `Internationa / l`。
行数跟着格子高度给（最多 6 行），地方不够时先压课名的行数，把高度让给地点。

文件名带比例后缀（`课表-2026-10-03-手机壁纸.png`），导几张不会互相覆盖。

> 「分享 / 存到相册」那颗按钮按用户要求撤掉了（`navigator.share` 那套代码也一并删除）。

弹窗底部那行只留"尺寸 · 比例"，不再写"手机上看不清就长按图片保存到相册"
（用户要求去掉那句说明；长按保存本身仍然有效）。

另外两处按用户要求删掉的说明文字：拉取成功后的「读到了，确认一下再导入」
（现在成功后直接把状态行收起来——结果列表和「导入这些课」按钮已经说明问题了），
以及预览摘要里"跳过 N 行（缺时间/缺代号）"的括号部分。

![导出的课表图片](docs/timetable-export.png)

几个实现上的选择：

- **canvas 手绘，不引第三方库**。这个页面是零依赖的（离线可用、加到主屏也要能跑），
  `html2canvas` 那类库还得把 DOM、字体、背景重放一遍，体积和不确定性都不划算——
  而周课表就是"几天 × 几小时"的网格加几个方块，几何很确定。
- **排版和画图分开**：`layout(courses)` 是**纯计算**（排哪几天、时间轴起止、
  每节课在第几车道），不碰 canvas，所以能在自检里直接单测（`[55]` 那 11 条）。
  `draw(ctx, model)` 只负责按算好的坐标画。
- **2 倍像素输出**（`scale: 2`）：5 天的课表逻辑尺寸 842×644，出图 1684×1288，够清楚。
- **列**：周一到周五固定画，周六/周日**有课才加**一列；6 列以上时列宽自动收窄。
- **时间轴**：按实际课程取范围，上端取整点（时间刻度是整点的）、下端取整半小时
  （按整点收的话最后一节课下课后会多一大截空白）；只有一节课时至少撑 6 小时。
- **撞车并排**：同一时段两节课并排两车道，而且**车道数按重叠簇算**——
  上午两节撞车不该把下午单独的那节挤成半宽（日历 App 都是这么做的）。
- **窄格子不写地点**：跟别人并排时格子只有一半宽，硬塞地点会断成 `Academ / ic…`，
  所以宽度小于 88px 就只写课名和时间。
- **换行优先在空格处断**（第一版按字符硬断，画出来是 `SAT 1000-A Lectu / re`，
  截图一看就发现不对）：中文本来就按字符走，英文按词走。
- **主色跟着页面主题**（从 `--accent` 读），但**底色不用页面上那套半透明玻璃**——
  图片没有背景视频，要的是一张干净、能直接发给别人的图。
- 没有课程时不画空图，直接提示"先导入或新增课程"。

### 提示条（右上角那条 toast）的两条规矩

- **撤销按钮在右边**：提示条改成横排（文字在左、按钮用 `margin-left: auto` 顶到最右、
  垂直居中）。原来按钮在文字下面占一整行，看着像"另一条提示"。
- **同时最多 3 条**：语音播报、删课撤销、导入结果这些凑一块能把整页占满，
  所以 `toast()` 里加了一句 `MAX_TOASTS = 3`，超了就把最老的那条挤掉。

## 从课表截图导入

「课表」页 → 从课表截图导入：截图课表页面，按 Ctrl+V 粘贴（或者把图片拖进去、
点一下选文件），十秒左右会得到一份可编辑的课程清单，核对后点「确认导入」。

### 为什么用截图 OCR

如果教务系统能导出 `.ics` 或者有可保存的整学期页面，解析文件会准得多。
但多数情况下手机上只拿得到一张截图，OCR 是唯一的自动化路径。

### 原理：不是「认字」，是「还原表格」

单纯把字认出来没用，还得知道每个字属于哪一天、哪个时间。所以真正的关键是
**用表格的几何结构还原内容**：

1. **表头**（Monday…Friday）决定每一列的横向范围
2. **左侧时间刻度**（8:00 / 9:00…）拟合成一条纵坐标 → 时刻的换算直线
3. 落在同一列、且纵向连成一片的文字，就是**一个格子 = 一节课**
4. 每个格子里的文字按行合并，再用规则解析出代码、课节号、类型、时间、地点

这样做的另一个好处是**不依赖 OCR 的阅读顺序**——Tesseract 按什么顺序吐出文字
都无所谓，因为我们只用到每个词的坐标。

### 已经处理掉的几个坑

这几个都是拿真实截图试出来的：

- **彩色底上的小字被自己的预处理抹掉**（2026-10-03 用户那张 CUSIS 课表截图）：
  课程格子是**浅橄榄绿 #B6D192 + 黑字**，结果一个字课都读不出来。实测三种像素处理：

  | 像素处理 | 读到 | 星期表头 | 格子里那节课 |
  | --- | --- | --- | --- |
  | 原图 / 灰度 / 增强对比 | 42–48 词 | ✓ `Monday Tuesday…` | ✗ 一个字没有 |
  | 抹掉彩色底 | 147 词 | ✗ `Tire Koray TUesdsEy` | ✓ `MATH 2058 - -` |

  两遍各读对一半，所以一条课也拼不出来。原因：原来的规则是"**又亮又彩色就整片抹白**"，
  对浅色底的大字没问题，但**彩底上的小字会被误抹**——反锯齿的笔画本身就被底色染成浅色，
  一亮就被当背景抹掉，笔画断成几截（表头就是这么读花的）。
  而灰度那遍反过来：格子那整片浅绿被 Tesseract 的版面分析当成图形丢掉，只读出表头。

  修法：新增**局部二值化**（自适应阈值）并放在第一位——拿"周围一圈的平均亮度"当背景，
  比它暗 32 以上的算文字。浅绿底上的黑字照样"比背景暗"，彩底上的反锯齿小字也保得住，
  顺手还能把白底上的浅灰框线（反差约 25）滤掉。积分图算邻域均值，2000×2000 几十毫秒。
  同一张图重跑：**试了 3 遍就出 12 条课**（原来 9 遍 0 条、耗时 4 分钟）。
- **时间刻度被裁掉首位数**。截图边缘常常把 `10:00` 截成 `0:00`，直接信 OCR 会得到
  错误的时间轴。做法是强制让时刻严格递增，不够就加 60 分钟补回来。
- **地点会折行**。`Lee Shau Kee Building LT3` 在格子里是两行，必须把剩余的行拼起来
  再解析，只取最后一行会得到半个楼名。
- **折行后教室号会被当成课节号丢掉**。`Lee Shau Kee Building` / `LT2` 分处两行时，
   单独成行的 `LT2` 长得和课节号一模一样，原来会被误排除。现在改成：
   地点只取**时间那一行之后**的内容——课表顺序固定是
   「代号 → 课节 → 类型 → 时间 → 地点」，比按形状猜稳得多。
- **纯数字的教室号折行后会被当噪声丢掉**。`Y.C. Liang Hall` / `104` 分开两行时，
   `104` 不含任何字母，被"必须含字母"的规则挡掉了。现在时间行之后的内容放宽到允许数字。
   这一条藏得比较深——之前 11 个地点测试全是单行写法，一直没暴露。
- **课节号会另起一行**。`BMEG 2410 - -` 下面单独一行是 `T02`，得往后找。
- **上下紧挨着的两节课**不能被合并成一条，靠文字间隙的中位数判断分界。
- **`Waiting:` 前缀**表示候补，会被单独标出来提醒你确认。
- **`No room required` 不是地点**，是"这节课不需要教室"（体育、实习、线上课常见）。
  要是照字面收进来，会平白多出一栋叫「No room required」的楼，之后还得手工删。
  现在这一类的写法统一认成**未指定**：`No room required`、`No rooms required`、
  `No room req'd / needed`、`Room not required`、`No venue / classroom / location required`，
  连识别漏词只剩 `No room` 的短版本也认。
  它和「地点待定（TBA）」是两回事：前者本来就没有地点，后者是还没公布、要自己补。
  识别预览里那条的楼栋下拉会显示「（不需要教室）」，不会劝你去新建楼栋。

> 导入预览里的**逐条黄字说明只留真正有用、要动手的**：
> 候补（Waiting）、时间没读准、模糊匹配的把握度（`自动匹配 83%`）、
> 以及"这栋楼不在列表里、导入时会新建、之后要补坐标"。
> 「地点待定，导入后需要自己补」不再逐条刷屏——下拉框显示「（未指定）」已经说明问题。
> 黄框只跟着还写着原因的提示走，不会出现"标黄但一个字都没说"的行。

还有两个更隐蔽的：

- **类型词被判成地点**。识别引擎开着"保留词间空格"，很容易把
  `Interactive Tutorial` 读成 `Interactive  Tutorial`（双空格），
  而类型词的判断原来是严格相等，漏掉之后它就混进地点里了。
  现在比较时忽略空格和标点，并且在拼好地点之后还会再扫一遍把它摘掉。
- **类型词被拆成两行**。`Interactive` 和 `Tutorial` 各占一行时，两行都不是完整的
  类型词，谁都拦不住。现在会把"相邻两行拼起来正好是类型词"的情况先合并回去，
  而且只在这种精确情况下才合并，`Lee Shau Kee` + `Building LT3` 这种正常折行不受影响。

### 识别不准怎么办

结果只是一份草稿，**导入前请核对**。所有字段都能直接改：星期、时间、课程名、
楼栋、房间；不要的可以「移除」。有问题的地方会标黄并写明原因。

识别效果主要取决于截图质量，几个建议：截整张课表（包含星期那一行和左侧时间刻度）、
别用夜间模式的暗色主题、避免缩放后的小字。

失败时页面会说明卡在哪一步，展开「识别详情」还能看到引擎实际读出来的原文。
三种典型情况：

| 提示 | 含义 |
|---|---|
| 一个文字都没读出来 | 图片太小或太糊。放大课表区域重新截，别截整个手机屏幕 |
| 读到了文字但没找到表头 | 截图里缺少 Monday…Friday（或周一…周五）那一行 |
| 找到表头但拼不出课程 | 表格结构和预期差得多，把「识别详情」里的原文发来就能定位 |

### 什么样的格子才算一节课

为了避免把页面上的零碎文字当成课程，判定标准卡得比较严，**两个条件缺一不可**：

1. **课程代号必须是 4 个字母 + 4 位数字**，例如 `BMEG 2210`、`ENGL 1001`
   （字母必须大写，所以 `Room 1234` 这类不会被误判）
2. **必须有能识别的课程类型**：Lecture / Tutorial / Interactive Tutorial /
   Laboratory / Assembly / Seminar / Workshop…

代号和类型都会各自进入课名，所以结果是 `BMEG 2210-T02 Interactive Tutorial`
这样的全名。

**数字位认错会被自动纠正。** OCR 经常把 `0` 读成 `O`、`1` 读成 `I` 或 `l`、
`5` 读成 `S`、`8` 读成 `B`，这些都会纠回来——`BMEG 22l0` 会变成 `BMEG 2210`。
原始文字会留底在「识别详情」里备查。

**被丢掉的格子会列出来。** 展开「识别详情」能看到每条被丢弃的原因和原文，
例如「没有找到 4 字母 + 4 数字的课程代号：ENG 1003 - EE / Lecture / ...」。
这样万一你学校的代号格式不是 4+4，一眼就能看出来，而不是只发现"少了几条课"。

### 技术细节

- 引擎是 **Tesseract.js**，纯浏览器运行，免密钥、免服务器，线上静态托管也能用
- **按需加载**：不打开这个功能就不会下载任何东西，基础页仍然零依赖
- **每一种外部资源都配了备用站点**：引擎脚本有 jsdelivr 和 unpkg 两个源，
  语言包有 projectnaptha 和 jsdelivr 两个源，一个不通自动换下一个
- 首次使用下载约 10 MB 模型，之后浏览器会缓存
- **只认英文**：课表上的课程代号、时间、教室号本来就是英文数字。
  以前这里有个「课表里有中文」的开关（勾上会多下一份中文模型、识别也慢一截），
  按用户要求去掉了；真要认中文，把 `js/app.js` 里 `OP.Ocr.run` 的 `lang` 改成
  `"eng+chi_sim"` 即可
- 图片在浏览器里**先放大到约 2000 像素宽**，再按"抹彩底 / 灰度 / 增强对比"三种方案
  分别识别，取效果最好的那次
- 表格用哪种页面分割模式最好因图而异，所以同一个像素方案会**依次跑 6 / 4 / 11
  三种模式，然后取并集**。换一遍读漏的格子往往不一样，并集能把丢掉的课补回来；
  同一条记录按「星期 + 起止时间」或「星期 + 代号 + 课节 + 类型」判定，
  撞车时留信息更全的那条
- 图片不上传，全程在本机完成

> **踩过的坑**：Tesseract.js 从 5.0 起改了默认输出，`tsv` 不再默认生成，
> 而解析完全依赖 TSV 坐标，结果是"识别成功但一个字都拿不到"。
> 现在识别时会显式要求 `tsv` 输出，并且按 TSV → words → lines → blocks 依次兜底，
> 换引擎版本也不会再空手而归。

> **踩过的第二个坑**：课表格子通常是**浅绿、浅蓝这类彩色底**。先转灰度再二值化时，
> 背景的亮度落在文字和白色之间，容易被一起判成"黑"，结果**整个格子的字全没了**——
> 只有白底上的表头和时间刻度能读出来。现在默认先做一步"抹掉彩色底"：
> 浅色的彩色像素直接变白，深色文字（不论有没有颜色）原样保留。
> 处理方案会依次尝试"抹彩底 → 只转灰度 → 增强对比"三种，取效果最好的那次。

> **顺带一提**：挑结果时不能只看"识别出几条课"。某种处理可能把同一段文字
> 拆成好几条残缺记录，条数反而更多。所以评分里**完整（有地点、有时间）的课权重最高**。

## 几个说明

### 语音播报

用的是浏览器内置的语音合成（Web Speech API），不联网、不花钱、不依赖第三方服务。

### 楼栋怎么念

播报里念楼栋用的是**中文名 + 英文简称**，例如：

```
李兆基樓 Lee Shau Kee，LT2
潤昌堂 Y.C. Liang，106
科學館 Science Centre，L3
伍何曼原樓 Wu Ho Man Yuen，305
```

中文全名让人一听就懂，英文简称对得上现场指示牌和时间表上的写法。
英文部分会去掉结尾的通用词（Building / Hall / Centre / Block…），
但**至少保留两个词**——否则 `Science Centre` 会被削成没意义的 `Science`。
结尾不是通用词的长名字（如 `Yasumoto International Academic Park`）保持原样。

只有一种语言时就用那一种，所以手工录的中文楼名不会被念成空白。

**只有播报用这个念法，界面显示不变**——列表、时间轴、路线页里仍然是楼栋的显示名
（`Lee Shau Kee Building LT2`）。因为看的时候要能对上时间表原文，听的时候要顺耳。

有两条系统限制绕不过去：一是 **iOS 上第一次播报必须由用户点按触发**，
所以页面上保留了「今日课表播报」这类按钮，自动提醒要等你手动点过一次之后才会响；
二是**页面切到后台时浏览器会暂停脚本**，所以提醒只在页面处于前台时可靠。

要做真正的后台提醒，需要套一层 iOS 壳，用系统的本地通知替代 —— 这正好是
下一步把页面打包成 App 的理由。

### 定位

必须走 `https` 或 `localhost`。手机上首次打开会弹权限申请，允许之后
页面每 4 秒更新一次位置。

> 「用当前位置当模拟点 / 清除模拟」这两个按钮按用户要求去掉了。
> `settings.simulate` 这个字段还留着并且仍然生效（旧存档里如果存过模拟点，
> 位置还是按它走）——只是界面上不再提供入口。要清掉它，
> 「设置 → 数据 → 恢复默认数据」会把设置一起复位。

### 路线是怎么算的

没有引入任何地图 SDK，因为那需要申请 key 并且按调用量计费。这里的做法是：

1. 用 haversine 公式算当前位置到目标楼栋的**直线距离**
2. 乘上「路程系数」（默认 1.3），折算成实际要走的距离
3. 除以步行速度（默认 75 米/分钟），得到步行耗时
4. 出发时间 = 上课时间 − 步行耗时 − 到楼缓冲，且**不会早于上一节课下课**

所以它是估算，不是导航。需要真实的转弯路线时，点行程卡片里的地图按钮跳转。

### 地图跳转：直接唤起 App

每段行程下面有 5 个入口：高德 / 百度 / **Google 地图** / 苹果地图 / **复制坐标**。
按钮上显示的地点名就是目的地，点开会**直接唤起手机上对应的 App**（装了的话），
没装才退回网页。

这是靠 **https 通用链接（universal link）** 实现的——`maps.apple.com`、
`www.google.com/maps/dir` 这些地址系统认识，装了对应 App 就直接交给 App 处理，
浏览器不会先闪一个网页。

> **为什么不用自定义 scheme**（`comgooglemaps://`、`iosamap://` 这类）：
> 那种链接在**没装 App 时是死链**，点了完全没反应；而且 iOS Safari 每次都会弹一个
> 「是否打开某某 App」的确认框，反而更啰嗦。通用链接两种情况都能正确处理。
>
> 一个例外：**如果以后把页面套壳成 App（WKWebView）**，通用链接不会交出控制权，
> 那时才需要改用自定义 scheme 或由原生侧处理。这是套壳时要记得改的地方。

坐标细节：Google 和苹果地图用标准 WGS-84，高德用 GCJ-02，百度用 BD-09，
所以每个按钮的坐标是各自算过的——直接用同一组坐标会偏几百米。

> **「复制坐标」是替代原来的「其他地图」的。** 原来那个用的是 `geo:` 协议，
> 本意是"让系统自己挑一个地图 App"——**那是安卓的标准**，Android 收到会给
> 你列出所有能处理它的地图让你选。但 **iOS 根本不认这个协议**，
> iPhone 上点了没反应。
>
> 所以换成「复制坐标」：`31.232000, 121.471000` 这样的文本，
> **任何地图 App 的搜索框都能粘**，两端都能用。

### 高差也算进去（爬山校园必备）

港中文、重庆的大学这类**建在山上的校园，楼与楼之间高差能上百米**。
只算水平距离的话，从山脚走到山顶会被严重低估。实测数据：

| 楼栋 | 海拔 |
|---|---|
| Y.C. Liang Hall | 146 米 |
| Lee Shau Kee Building | 119 米 |
| Science Centre | 107 米 |
| Lady Shaw Building | 99 米 |
| Wu Ho Man Yuen Building | 37 米 |
| Esther Lee Building | 33 米 |
| Yasumoto Int'l Acad Park | 32 米 |

最高和最低差 **114 米**——从康本学园走到润昌堂，等于爬 38 层楼。

所以步行时间改成这样算：

```
等效距离 = 水平距离 × 路程系数  +  爬升 × 爬升系数
步行时间 = 等效距离 ÷ 步行速度
```

「爬升系数」默认 **8**，取自登山常用的 Naismith 经验值（1 米爬升 ≈ 8 米平路），
在设置里可以调，**设成 0 就完全不考虑高差**。

效果（康本学园 32 米 → 润昌堂 146 米，水平 826 米）：

| | 步行时间 |
|---|---|
| 不算爬升 | 11.0 分钟 |
| 算上爬升（118 米） | **23.2 分钟** |

只下坡不算爬升——`max(0, 终点海拔 − 起点海拔)`，所以从山顶往下走不会被罚时间。
界面上**只有爬升超过 3 米才显示这一项**，下坡的行程段不会出现"爬升 0 米"这种噪声。

> 踩过的坑：多段行程里，通往下一段时起点会被重建成 `{ lat, lng }`，
> **海拔字段被丢掉了**，结果只有第一段显示爬升，后面全按"未知"处理。
> 现在重建起点时会把 `elevation` 一起带上，自检里也加了断言：
> 「四段行程都要算得出爬升，不只是第一段」。

### 海拔从哪来

用 **Open-Meteo** 的免费海拔接口，不需要 key，也允许浏览器直接跨域调用。

- **楼栋海拔**：设置 → 校区楼栋 → 「获取海拔」，一次补齐所有缺的（接口一次收 100 个坐标）
- **你的位置海拔**：定位更新时自动查一次，查到的值会跟着位置对象走，不会反复请求
- 查询结果按坐标缓存 24 小时（海拔不会变）
- 查不到就按平地算，不影响其它功能——**海拔只是让时间更准，不是必需项**

> 有一点要区分清楚：**只有一边有海拔时标记为「未知」，不会当成平路**。
> 界面上显示"爬升 0 米"和"没有海拔数据"是两回事。

跳转前会做一次 **WGS-84 → GCJ-02 → BD-09 的坐标转换**：GPS 拿到的是国际标准坐标，
而高德、百度用的是加密后的火星坐标，两者在国内差几百米，不转换会导到隔壁楼。

### 数据存在哪

设置页「数据」卡片里能看到三个版本号，出问题时先看这三个：

| 格子 | 含义 | 例子 |
|---|---|---|
| 应用版本 | `OP.APP_VERSION`，手写在 `data/defaults.js` | `v1.0.0` |
| 构建版本 | 部署时给 js/css 加的 `?v=` 时间戳，页面直接从 script 标签读回来 | `mumk3i0c` |
| 楼栋数据 | `data/buildings.js` 里的 `version`，靠它判断要不要把新补的楼并进本地 | `v2` |

「构建版本」显示**本地**说明是在直接打开源码（没有部署脚本加的 `?v=`），
不是线上那一份——刷新后还是「本地」的话，多半是打开方式不对。

全部存在浏览器本地的 localStorage 里，不上传任何服务器。**楼栋、课表、设置
分开存**，各用各的键：

| 内容 | 键 |
|---|---|
| 楼栋（校区名 + 楼栋列表） | `olympic-protocol.buildings.v1` |
| 课表 | `olympic-protocol.courses.v1` |
| 设置 | `olympic-protocol.settings.v1` |
| 已经播报过哪些提醒 | `olympic-protocol.fired.v1` |

分开存的好处：

- 换课表不会碰到楼栋，清空楼栋也不会把课表带走；
- 楼栋可以整体换成别的地方，课表照旧；
- 楼栋数据有独立的默认值（`data/buildings.js`），课表没有。

更早的版本把三样东西塞在一个键（`olympic-protocol.data.v1`，再往前是拼错的
`olympic-protocal.data.v1`）里。页面第一次读的时候会自动拆成上面三个键，
拆完把老键删掉，**老访客的课表和楼栋不会丢**。

换设备或换浏览器请用「导出 / 导入」——导出仍然是一个整包 JSON，
楼栋、课表、设置都在里面。清空浏览器数据会丢失，所以建议定期导出一份。

### 更新默认楼栋

`data/buildings.js` 不是手写的，是从一次导出生成的：

```bash
node tools/make-buildings.js 导出的存档.json
```

存档在页面里点「课表 → 导出」就能拿到（文件名类似
`olympic-protocol-2026-09-28.json`）。脚本**只取楼栋**，按名字排好序写进去，
课表和设置不会进默认数据——那两样是每个人自己的。

以后在校区里又录了新楼，导出一次、跑一遍这个命令，默认楼栋就跟上了。

有几栋楼是导出里没有、但要留在默认数据里的（脚本里叫 `EXTRA`，
例如**夏鼎基運動場 Sir Philip Haddon-Cave Sports Field**）。
它们写在脚本里，重新生成时才不会被抹掉；坐标从 OpenStreetMap 查，
海拔用页面同一个接口（Open-Meteo）取。

脚本里还有一份 `ALIAS_EXTRA`，用来**给已有的楼栋补课表上的写法**。
最典型的是 `Science Centre`：OSM 把它拆成了科學館東座、北座、南座和
大學科學館（University Science Centre）好几条，课表只写 `Science Centre`——
按模糊分算，东座和科學館并列，先出现的东座就赢了，但那不是课表指的。
把它挂成大學科學館的别名，就变成精确匹配，不用再靠分数碰运气。

> 补别名这件事也得**送到已经存过数据的用户那里**：默认值改完，
> 用户本地那份不会自动跟着变。下面这条就是解决它的。

#### 默认楼栋换版本时：强制采用（整份替换）

`data/buildings.js` 里有一个 `version`，内容一变就 +1（不用手改，脚本自己算）。

页面打开时比一下版本号：**本地那份比默认数据旧，就把本地那份整份换成新版默认数据**，
然后把版本号记下来，不会每次打开都换一遍。

**为什么是"整份替换"而不是"只补不改"**：用户清过一轮默认数据（把变电箱、
村公所这类用不上的点删掉了），"只补不改"的话本地那份旧列表会一直留着——
**删掉的那些根本删不掉**。所以按用户要求改成强制采用。

代价说清楚：**本地自己加过、改过的楼栋会被覆盖**。楼栋数据从此以
`data/buildings.js` 为唯一来源；要自己加楼，加完导出、跑一遍
`tools/make-buildings.js` 重新生成默认数据。

三条规矩：

- **强制采用**：本地列表 = 新版默认数据（同名的就地覆盖，本地多出来的移掉）；
- **本地列表是空的就不动**——那是用户自己点「清空全部」清掉的，不硬塞回来；
- 换完会弹一句提示：「楼栋数据已换成新版 · 共 N 栋（新增 X 栋、移除 Y 栋）」，
  让用户知道为什么自己加的楼不见了。

> **校区名不动**：那是用户可以在设置里改的标签，不属于楼栋数据。

## 校巴：自动推荐坐哪趟车

路线页每一段行程下面，会多出一块**校巴方案**：

```
校巴
[4] 環迴線
逸夫書院（下行）上车 → 大學站 下车
走到车站 2 分 + 车程 8 分 + 走到教室 3 分 = 合计 13 分 · 约每 20 分钟一班  比走路快 6 分
```

**不写"几点到"**。校巴到站时间太不稳，报了反而误导——所以只给**稳定的那部分**：
哪几个站、走多久、车程多久、大概几分钟一班。要赶哪一班、几点出门，自己按班次间隔推。

**上车站取离你最近的那个，下车站取离教室最近的那个**（按走过去的时间排，
不是直线距离）。最近那个站没有车能坐，才退到第二近的。

上车那一头的搜索半径是 **650 米**；**下车那一头放宽到 1200 米**——
目的地附近能用的站多算几个，可选的线路才多。

**只要能到目的地附近的车站，这条线就会列出来**——不会因为"比走路慢"或者
"赶不上这一节"就藏起来。慢的会写明「比走路慢 X 分」，由你自己判断。
同一条线只出现一次（同一趟车在近站远站都上得去，列两遍只是重复）。

**线路之间按"坐车总耗时"从短到长排**，谁快谁在前。

### 地图上会标出车站

简图和真实地图上都会把这一段用到的校巴站画出来（简图上是琥珀色菱形 + 站名，
真实地图上是小圆点 + 悬停提示）。取景范围也把这些站算进去，不会跑到画面外。

**地图上的连线是三截**：我的位置 → 上车站、**上车站 → 下车站**、下车站 → 上课地点。
原来那条"我的位置 → 第一节 → 第二节"的行程链已经去掉——校巴不一定直达，
把地点串起来看着像路线，其实没有指导意义。

三截里中间那截是**坐车**，不是走路，所以画法不一样：走路是粉色细虚线，
坐车是紫色粗点线（简图和街道图都是这套区分，图例里也写了）。
注意它是**两个车站之间的直线**，不是巴士实际走的路线——简图本来就是示意图，
要看真实道路就切到街道图。

### 停运的线路自动折叠

按**当前时间**判断每条线在不在开（今天开不开 + 现在在不在服务时段内）：

- 在开的正常列出，排在前面；
- 停运的（白天看 H 线、白天看 N 线、早上 9:10 前的转堂校巴、**公众假期里的 1 号线到 7 号线**……）
  **收进一个可展开的「现在停运的线路」**里，不占地方，但要查随时能展开。

所有线路都会显示出来，不会因为"现在不开"就消失。

### 放假那天只剩假日线（H）

校历里的**公众假期 / 大学假期**，星期一至六的线路一律停开，只剩假日线 H——
数据里 H 的服务时段本来就是 `{ days: ["sun","holiday"] }`，所以只要把日期键
从"星期几"换成 `holiday` 就对了。详见下面「校历」那一节。

### 没方案的时候会写明原因

"没有校巴方案"其实是三种完全不同的原因，直接说清楚，免得以为是坏了：

| 显示 | 意思 |
|---|---|
| 附近没有校巴站 | 起点 650 米、终点 1200 米内都没有站 |
| 没有线路从上车站坐到下车站（校巴单向） | 有站，但那条线是反方向的 |
| 这条线今天已经收车了 | 有站有线路，但今天没班次了 |
| 校巴模块没加载——页面是旧缓存 | HTML 是旧的（里面没有 `js/shuttle.js`），刷新一次 |

最后一条是专门用来区分"没车"和"页面旧了"的——这两种以前长得一模一样，
都是什么都不显示，排查起来很费劲。

### 怎么算的

1. **找站**：起点、终点周围 650 米内的车站都算候选，最近的三对拿来试。
2. **找车**：在每条路线上找一对「上车站 → 下车站」，要求下车站排在上车站**之后**。

   **所有路线都是单向的，不能绕回去**——到了终点所有人必须下车。
   所以 3 号线从「逸夫书院（下行）」坐不到「科学馆」（科学馆在这条线的前段），
   坐过站也不会被带回来；要往回走得换另一条线或者走路。
3. **等车**：路线图给的"每小時開出時間"是**从首站开出**的时刻，所以要先按
   「首站 → 上车站」的行驶时间换算，再找你到站之后的第一班。
4. **加起来**：走到车站 + 等车 + 车程 + 下车走到目的地，和走路比谁先到。

### 海拔算进去了

**每一步都算海拔**，这在爬山校园里最要紧：

| 那一段 | 怎么算 |
|---|---|
| 走到车站 / 下车走到教室 | 水平距离 × 路程系数 + **爬升 × 折算系数**（和页面算步行时间同一套） |
| 坐车 | √(水平² + **高差²**) —— 山路爬升就是实打实多走的路 |

所以同一个站，从山上走下去和从山下走上去，时间能差好几倍；
"哪个站最近"也是按**走过去要多久**排的，不是按直线距离。

车站海拔来自 Open-Meteo（和页面「获取海拔」同一个接口），查一次存在
`tools/stop-elevations.json`，生成时不再联网。

> 行驶时间仍是用站点直线距离估的（乘 1.15 的道路系数，按 330 米/分钟 ≈ 20 km/h
> 算，每停一站加 15 秒）。校园里绕路多，**车程只是量级参考**，不是真实时刻表。
> 校巴速度可以在「设置 → 提醒与步行参数」里改。

### 附注里的条件会认真对待

路线图上带 # 的站不是每班都停，程序按两类处理：

| 附注 | 处理 |
|---|---|
| 「逢 00 分開出的班次才停」「逢 31 至 00 分」 | 可以精确判断，**不满足就换下一班** |
| 「只在教學日」「只在非教學日」 | 取决于校历，算不出来 → 照常给方案但注明，并且**排在没前提的方案后面** |

公众假期同理：程序只看星期几，认不出假期，所以假日线 H 只按"星期天"判断。

## 校历：放假不上课、校巴只剩 H 线

数据在 `data/holidays.js`，抄自香港中文大学教务处注册及考试组
《2026-27 年度校历 —— 选课日期、开学礼、大会及假期》。页面原文那两条注也抄在里面：
**所有公众假期均为大学假期**；**大学假期及农历新年假期期间将不会安排课堂**。

一共 24 条，分三类，课和车分别怎么处理：

| 类型 | 例子 | 上课 | 校巴 |
|---|---|---|---|
| `holiday` 公众假期 / 大学假期 | 国庆日、中秋翌日、农历新年那一周、圣诞、受难节…… | 不上 | **只有假日线 H** |
| `noClass` 停课日（不是假期） | 本科入学资讯日（10/17）、第九十七届大会（11/12） | 不上 | 照常 |
| `partial` 只停一段 | 开学礼（9/7）停到 13:30 | 13:30 前不上 | 照常 |

几条想清楚才这么定的：

- **农历新年那一周（2027-02-05 ~ 02-11）里只有 2/6、2/8、2/9 是公众假期**，
  其余四天是大学假期（数据里的 `publicHoliday` 字段标着）。程序上七天一视同仁：
  不上课 + 只开 H 线——要的是"假期只剩假日线"这个结果，不是去分辨两者的法律区别。
- **开学礼不是一整天**。那天上午的课会消失，所以主卡写的是
  「今天有 N 节课因本科生開學禮停課」，而不是留一句"今天没有课"让人以为课表丢了。
- **停课日不是假期**。入学资讯日那天不上课，但校巴照常跑——课表停课和校车停开是两件事。
- **校历只到 2026-27**。范围外的日子按普通日子处理：宁可多显示几节课，
  也不要因为"查不到"就把一整天的课吞掉。

界面上的表现：放假那天主卡写「放假 / 今天放假 / 国庆日 · 校巴只有假日线（H）」，
今日课程列表写「放假：国庆日」，**倒计时和「距离 / 步行 / 建议出发」那一行收起来**
（那天它们全是空话，留着就是一排破折号）。

顺带记一个自检里踩的坑：有几个播报用例原来拿 `2026-10-01`（星期四）当"普通的一天"，
校历一接上，那天整天没课，三条断言当场变红。改成 `2026-10-08`（同样是星期四、
不是假期）了——这件事本身倒是证明校历真的生效了。

## 自定义路线

路线页最下面有张「自定义路线」卡片：**自己选起点和终点**，两个下拉，
选完就自动算，不用再点按钮。

- **起点**可以是「我的位置」，也可以是任意一栋有坐标的楼；**终点**是楼栋。
  两个都是**可搜索的输入框**（和宿舍那个一样）：点一下列出全部，
  边打字边筛，**中英文、简体繁体、拼音首字母都认**
  （`蒙民伟楼` / `蒙民偉樓` / `mmwl` 都能找到 Mong Man Wai Building），
  回车或失焦时还会拿名字去兜一次底。
- 算的是和「去上课」「回宿舍」**完全同一套**：步行时间（含高差）
  + 校巴方案（走到车站 / 车程 / 走到终点 / 合计 / 约几分钟一班）。
- 起点终点同一条路会直接提示，不会算出一段"两边一样"的路线；
  起点选了「我的位置」但还没定位时，也会写明怎么办。
- 起点和终点**记在设置里**（`customFrom` / `customTo`），切走再回来还在，
  「起点终点对调」一键换向（起点是「我的位置」时没法对调，会提示）。

顺带修了一个老毛病：**「复制坐标」原来只绑在行程列表上**，返回宿舍和自定义路线
卡片里点了没反应——现在是全局委托，三张卡片都能用。

## 返回宿舍

路线页底部有一张「返回宿舍」卡片，跟去上课那套是同一套算法，只是终点换成宿舍。

**起点就是"我的位置"**（用户指定）。人在哪儿就从哪儿算，不再假设"你正坐在
今天最后一节课的教室里"。之前那个「从今天最后一节课的教室出发」的开关、
以及背后的 `settings.dormFromClass` 设置项都已经删掉了。

只有**取不到定位**时（没开权限、电脑上没有位置）才退回"今天最后一节课的教室"——
卡片上全空着比给个大概更糟。退回去时卡片标题会写清是哪栋楼，下面还有一句
"没取到定位，先按今天最后一节课的教室算（09:30–17:30 某某课）"，并且多一格
"下课后 17:30"，不会让人误以为是从当前位置算的。

给的东西和去上课一样：距离、步行时长、**爬升 / 下降**、校巴方案（走到车站 + 车程 +
走到宿舍 = 合计，以及约几分钟一班），外加高德 / 百度 / Google / 苹果地图的跳转按钮。

两点说明：

- **爬升和下降分开写，只有爬升折算成时间**。回宿舍大多是下坡，"下降 136 米"是有用的
  信息，但下坡不省时间（这是 Naismith 那套经验规则的口径），所以不参与计算。
- 宿舍的海拔**默认数据里没有**（OSM 不给），页面上第一次用到时按坐标查一次，
  查到之后记在内存里，不会反复去问。

### 宿舍数据从哪来

`data/dorms.js`，由 `node tools/make-dorms.js` 生成，数据来自 OpenStreetMap
（Overpass API），按关键词搜：**宿舍 / 舍堂 / 書院 / Hostel / Residence /
Dormitory / Hall**，另外把 `building=dormitory`、`amenity=student_accommodation`、
`tourism=hostel` 三种标签的也一起收。

现在收进来的是**港中文校园范围内 61 处**，自检里有一条专门盯着
"全部都在校园这个框里"，免得哪次把别的地方也抓进来。

其中有 2 处是**手工补录**（生成脚本里的 `MANUAL` 列表）：**晨興書院**、
**伍宜孫書院**。这两间书院本身就是宿舍，但 OSM 上标的是 `building=yes` + 书院面，
既不是 `building=dormitory`，名字也没被那串关键词捞进来，只能点名补——
坐标和 OSM 对象号都是从 OSM 取的（`way/230185998`、`way/194547401`），
不是自己编的。自检里有一条盯着"这两条在名单里、带中文名、带 OSM 对象号"。

**每条宿舍存两个名字**，不是一个：

| 字段 | 内容 | 例子 |
|---|---|---|
| `name` / `nameEn` | 英文名（课表和地图上的写法） | `Chih Hsing Hall` |
| `nameZh` | 中文名 | `知行樓` |
| `alias` | 其他写法（OSM 的 `alt_name` 等，比如五旬節會樓的「五高」「五低」） | `Chih Hsing Hall 知行樓` |

中文名是**独立字段**，不是塞在别名里：列表和路线卡片显示的是「英文 中文」并排
（只写 `Bethlehem Hall` 或只写 `伯利衡宿舍` 都有人认不出来），输入框中英文都能搜，
中文名也会进播报用的名字表。61 处**全部有中文名**，自检里有三条盯着这件事
（有没有 `nameZh`、里面是不是真有汉字、是不是把英文名抄了一遍）。

刷新数据：

```bash
node tools/make-dorms.js --fetch    # 联网抓一次，存成 tools/dorms-overpass.json
node tools/make-dorms.js --list     # 先看看抓到了啥、哪些被筛掉了
node tools/make-dorms.js            # 写进 data/dorms.js
```

> 抓取时的坑：一个请求里塞五条条件必超时（Overpass 直接 504），
> 所以脚本是**拆成五条小查询分别重试**、再合起来的；两条查询之间还留了 600ms 间隔。

### 要补一条不在名单里的宿舍

先在 OSM 上确认真有这栋楼（用 Nominatim 按名字搜最快，Overpass 按名字做正则
很容易 60 秒超时），拿到**对象号和坐标**，然后加进 `tools/make-dorms.js` 的
`MANUAL` 列表，再跑一次生成。规则是：**宁可没有这条，也不要自己编坐标**。

注意取哪一条：同一个地方 OSM 上常有"`amenity=college` 的面"和"`building=yes` 的楼"
两个对象，隔着几十米。要取**楼**那个（人走到的是楼）。

补进去之后记得看一眼繁简/拼音表——数据里冒出新字，自检会直接报错提醒你加字。
`晨興書院`/`伍宜孫書院` 这次就带进来 5 个新字（晨興伍宜孫）。

### 名单不全 / 多出来了怎么办

OSM 是众包数据，"宿舍"这种东西有缺漏很正常（新书院的宿舍就常常没被单独标出来）。
名单是按 OSM 整理的，缺的走上面那条路补进 `tools/make-dorms.js` 重新生成，
不是让学生自己在页面上录坐标。

卡片上原来还有一条「**用当前位置添加宿舍**」——走到楼底下按一下、名字按最近的楼栋
预填——**按用户要求删掉了**（连着那张表单一起）。页面上的逻辑 `OP.Dorm.add / remove`
还留着，自检里那几条测试（自己加的不写回数据文件、默认那批删不掉）也都还在，
以后想把入口加回来，把按钮和表单贴回 `index.html` 就行。

**删除这个宿舍**留着——只对自己加的（`settings.addedDorms` 里的）生效，
走的是页面内确认弹窗，不是 `window.confirm`（内置浏览器里那个会被静默屏蔽）。
没有可删的时候整行一起收起来，不会留一段空行。

输入框是中英文 + 别名一起搜的（"知行"和 "Chih Hsing" 都能找到知行樓），
下面单独说繁简和首字母。

### 搜宿舍：简繁互通 + 中文首字母

港中文的宿舍名是繁体（知行樓、應林堂），但很多人打字用简体，也有人只想打几个字母。
所以搜索在比较之前先把两边**都统一成"小写 + 简体"**，并且额外支持**拼音首字母**：

| 你打的 | 结果 |
|---|---|
| `知行楼`（简体） | Chih Hsing Hall 知行樓 |
| `知行樓`（繁体） | 同上 |
| `应林堂` / `應林堂` | Ying Lin Tang 應林堂 |
| `zxl` | 知行樓 / 紫霞樓（两条首字母一样，按相似度挑） |
| `gjss` | 國際生舍堂一/二/三座 |
| `Chih Hsing` / `C.C. Staff` | 照旧按英文搜 |

**候选列表是页面自己渲染的，不是浏览器原生的 `<datalist>`。** 这一条是踩过的坑：
原生下拉只会拿你打的字去跟候选的**字面值**做包含匹配，它不懂繁简也不懂首字母——
打「汤」的时候候选写着「Adam Schall Residence 湯若望宿舍」，原生下拉直接是空的，
看起来就是"搜不到"，可搜索本身明明能命中。所以现在改成：**边打字边用
`OP.Dorm.search()` 出候选**（最多 8 条，再多提示"还有 N 条"），点一下就选中；
选中用 `pointerdown` 而不是 `click`——等 `click` 的话输入框会先失焦、
触发 `change` 把列表收掉，就点不着了。一条都没匹配上时给的是提示文字，不是空白。

实际做出来是一张**受自检保护的对照表**（`js/zh.js`）。它现在不只给宿舍用——
**校区楼栋、自定义路线的起点/终点都用同一张表、同一条匹配规则**。

| | |
|---|---|
| 表里多少字 | 619 个（数据里出现的 536 个汉字 + 它们的简体写法） |
| 表怎么来的 | `node tools/make-zh.js` 生成，**不是手写**：拼音取自 Unihan 系的 `pinyin-data`，繁简取自 OpenCC 的 `TSCharacters`，两份源表缓存在 `tools/` 下 |
| 为什么不装库 | 纯静态站点、没有构建步骤，为这个拉一个几百 KB 的转换库不划算；只收真正用到的字 |

这张表最怕的错是**漏字**——数据里以后冒出一个新字，没加进表，那个字的拼音就
悄悄没了，搜索看起来"有时候灵有时候不灵"。所以自检里是逐字验的：三个数据文件里
出现的每个字都必须在表里、每个字都算得出一个字母的首字母、每个字都能转出简体、
而且**简体写法算出来的首字母和繁体一致**。漏一个字自检直接报错。

> 首字母是**从头比**，不是"包含"。包含会产生误命中：输 `syt`（邵逸夫堂）
> 会连带命中「牟路思怡圖書館」（首字母 `mlsytsg` 里含 `syt`）。
> 每个名字各自从头比，既能搜到（别名的首字母也各算各的，比如五旬節會樓高座的
> 别名「五高」输 `wg` 能中），也不会误伤。

### 站序是怎么定下来的

官网每条路线页画的是**两列站序图**，站点在页面上的先后顺序和旅行顺序不是一回事。
定的依据有两条：

1. 主题 CSS 里 `.arrow-left` 用的是**向上**箭头图片、`.arrow-right` 用**向下**箭头图片
   —— 是固定画法，不是按路线变的；
2. 用无头浏览器把 14 条路线的每个站点**实际纵坐标**读出来核对，
   确认页面里的先后顺序就是图上的自上而下。

所以站序 = **起点 → 左列倒序 → 右列正序 → 终点**。

> 上下行是两个站位，不能合并：8 号线同一趟里"39 区（上行）"和"39 区（下行）"都要停，
> 合并成一个 id 就丢信息了。

### 怎么更新

```bash
node tools/make-shuttle.js
```

读 `tools/shuttle-source.json`（路线与站序）+ `tools/osm-stops.json`（OSM 站点快照）
+ `tools/stop-elevations.json`（车站海拔），
生成 `data/shuttle.js`。OSM 快照是查一次存下来的，不联网也能重新生成；
要刷新位置就重新查一次 Overpass，把结果覆盖进 `tools/osm-stops.json`。

改完跑一次自检，里面有一组专门盯这份数据：路线编号齐全、每组条数对得上、
每个站都有坐标且落在校园范围内、路线引用的站都存在、首尾同站的线首尾确实是同一个站、
时间先后说得通、附注有没有写进去。

> 收费穿梭小巴（up / down，$5.5 那两条）**没有收录**——附件里没有，
> 而且它是收费的另一个服务。需要的话再说。

## 课表代理（可选功能，默认不启用）

学校那个课表接口浏览器**直连不了**：预检和响应都没有 CORS 头，而且网页 JS 不允许设
`User-Agent`。想在页面上"输入学号密码直接拉课表"，中间必须有一层代理。

`worker/` 里就是这一层——部署在 Cloudflare Workers **免费版**上，只做
「转发一次 → 把 XML 里的 JSON 抠出来 → 原样返回」，不写日志、不落盘、不缓存。
完整说明（部署步骤、接口、四种上游写法、安全清单）在 `worker/README.md`。

三条已经落地的事实：

- **上游是官方 App「Student Class Timetable」的私有后端**（ASMX SOAP，
  `GetTimeTable(asP1, asP2, asP3)`），没有公开文档，参数含义是社区逆向出来的；
- 它**分不清"密码错"和"这学期没选课"**——两种情况都返回 HTTP 200 + 空数组，
  所以界面上只能说"没读到课表"，不能断言密码错；
- 这个 worker **不做自动重试**：密码错的情况下连发几次等于连错几次，会试锁账号。

> 部署与否都不影响线上页面：`worker/` 不在 `tools/deploy.js` 的搬运清单里，
> 页面用不到它就一直躺着，一行都不会上线。

### 页面这边怎么用（课表页的两张滑动卡之一）

「课表」页「全部课程」下面是两张左右滑动的导入卡，**默认停在「从学校接口拉取」**。
在那张卡上填学号、密码，点「拉取课表」→ 下面是预览 →「导入这些课」。

**代理地址和上游写法都写死在 `js/app.js` 里，界面上不出现**：

```js
var PULL_PROXY = "https://cuhk-timetable-proxy.<账号>.workers.dev/t/<口令>";
var PULL_MODE = "soap-aes";   // 实测只有加密的能读到课
```

> 代价说清楚：口令写进前端就等于**公开**了。真正的防线是那台 Worker 上的
> 「只允许 rhythmhill.com 这个来源拿到 CORS 头」+ 每 IP 每分钟 6 次的限流，
> 所以别人的网页调不动它、脚本硬刷也会被挡。想再紧一档，可以在 Cloudflare
> 控制台给它加一条 Rate limiting 规则。

几条刻意的设计：

- **密码从来不存**：`localStorage` 里只有学号（`pullSid`），密码用完立刻清空输入框，
  也不进任何日志。代理那台同样是收到就用、用完就丢——它没有数据库，响应还带
  `Cache-Control: no-store`。密码框的提示就写着"该网站不会保留你的任何个人信息"。
- **拉不到时不说"密码错"**，因为上游给的答案分不出来（见上）。文案是
  "上游返回 0 条——密码错和这学期没选课，学校给的结果是一样的"。
- **连不上代理时会自己分辨原因**：iOS Safari 对失败的 fetch 只会说一句
  "Load failed"，什么线索都没有。所以失败后会再发一个 **no-cors 探针**
  （这种请求不受 CORS 约束，只回答"网络能不能碰到那台代理"），于是能分开两种：
  - 探针能通 → "网络能通，但当前页面来源不在代理白名单里"，并把**当前来源**
    一起打出来（方便直接加进 Worker 的 `ALLOWED_ORIGINS`）；
  - 探针也不通 → "网络层面就到不了那台机器"（常见：当前网络屏蔽了 workers.dev、
    VPN、或手机上的广告拦截/DNS 配置）。
- **「原始字段」面板**：展开能看到上游返回的字段名清单和前两行的原文。
  字段名是照着逆向项目抄的、没人见过真实数据，所以这一页就是给你第一次联调时对齐用的
  （`js/timetable.js` 里每个概念都留了几个候选名，大小写和下划线都不计较）。
- **导入会去重**（同名 + 同星期 + 同时间 + 同教室算同一条），所以拉两次不会变成两份。
- **楼栋能自动补全**：上游自带教室名和经纬度，没匹配上的会新建楼栋并带上坐标，
  匹配上但缺坐标的会顺手补上——以前"课表地名对不上楼栋"那个老毛病，从这条路导入就没了。
- 「接口写法」那个下拉是给联调用的（`soap-plain` / `soap-aes` / `form-plain` / `form-aes`），
  哪种能拿到课表就用哪种，定了之后选"默认"即可。

### 上游真实字段（2026-10 第一次拉到数据时抄下来的）

一共 28 个字段：

```
STRM  STRM_DESCR  CLASS_NBR  CLASS_MTG_NBR  DESCR  CRSE_ID  SUBJECT  CATALOG_NBR
SSR_COMPONENT  CLASS_SECTION  START_DT  END_DT  MEETING_TIME_START  MEETING_TIME_END
MON  TUES  WED  THURS  FRI  SAT  SUN
FACILITY_ID  FDESCR  BLDG_CD  LAT  LNG  INSTRUCTORS  COMDESC  SSR_COMPONENT1
```

两个反直觉但很关键的点（都踩过）：

1. **星期是七个开关列**（`MON`…`SUN` 各自 Y/N），一门课一周上几天直接读得出来。
   **不要从 `START_DT` 去推**——它是这套上课安排的起止日期，不等于"第一节课那天"。
   所以映射先读这七列，一个都没勾才退回按日期推。一门课多个 Y 就是多个星期
   （我们的课程结构本来就支持 `weekdays: [2, 4]`）。
2. **明文那两种写法读回来是空的**，只有 `soap-aes` / `form-aes`（凭据 AES 加密）
   才有数据。所以默认接口写法是 **`soap-aes`**，页面每次都显式把 mode 发给代理，
   不依赖代理那台配的 `UPSTREAM_MODE`（那台现在还是 `soap-plain`，不影响）。

3. **上游没有"周次"字段**，时间上只有 `START_DT` / `END_DT` 两个日期。
   早先版本把这两个日期换算成教学周（"第 1–13 周"）显示，**现在已经不换算了**，
   直接把这一段日期照原样显示：`2026-09-07 – 2026-12-04`。

   > **`START_DT` / `END_DT` 是八位数字**（`20260907`），不是 `2026-09-07`。
   > 第一版解析只认带分隔符的写法，结果真数据一个日期都没解析出来——
   > 课表里"星期后面那截起止日期"整段消失（用户截图为证）。
   > 现在两种都认，而且会校验（7 位数字、13 月、2 月 30 日一律拒掉，不瞎归一）。

   这一步的教训留着：换算要依赖"学期开始日"，上游又是按学期返回的，
   一次跨两个学期（`STRM` 不同，比如 `2610` / `2620`）第二学期就会整体偏；
   再加上 `END_DT` 不一定是最后一次上课那天。直接显示日期省掉了所有这些歧义
   ——日期是上游给的原文，谁也翻译不错。跨学期时摘要里仍会写明
   "跨 N 个学期（… ×N 条）"，让你知道这批里有两个学期的课。

其余字段的用法：`SUBJECT + CATALOG_NBR + CLASS_SECTION` 拼代号、
`COMDESC` 是课型（Lecture / Assembly / Laboratory）、`FDESCR` 是地点
（拆成楼栋 + 教室）、`START_DT`/`END_DT` 就是课程那行小字上显示的起止日期、`INSTRUCTORS` 是老师、
`LAT`/`LNG` 直接拿来补楼栋坐标；`CLASS_NBR` / `CRSE_ID` / `BLDG_CD` 也一起留着，
以后要对账（比如和 CUSIS 上的班号核对）用得上。

还有个边界：楼名本身以数字结尾时（`Foo Building 7` 这种），
先削成 `Foo Building` 再匹配会认错——所以**先拿完整地名匹配**，
匹配上了就不再把末尾数字当教室号。

## 部署到线上

线上地址：<https://rhythmhill.com/olympicprotocol/>

（旧地址 <https://rhythmhill.com/olympicprotocal/> 留了一张跳转页，
之前发出去的链接仍然能打开。）

`rhythmhill.com` 由 `clubwebsite` 仓库托管在 GitHub Pages 上。GitHub Pages 的
自定义域名只能由一个仓库占用整站根路径，所以这个页面是作为
**`clubwebsite` 仓库的 `olympicprotocol/` 子目录**发布的。

更新线上内容：

```bash
node tools/deploy.js --push
```

它会把页面文件同步到 `clubwebsite/olympicprotocol/`，然后提交、推送，
GitHub Pages 大约一分钟后自动生效。不带 `--push` 就只同步文件、不提交。

### 每次部署都会换资源版本号

**光换 js/css 的版本号是不够的**：GitHub Pages 给 `index.html` 也发了
`Cache-Control: max-age=600`，所以刚部署完的 10 分钟内，浏览器手里那份旧 HTML
里指的还是旧资源——刷新也还是旧的（这就是"怎么改了没生效"的根因）。

所以部署脚本还会：

1. 把这次的构建号写进 HTML 的 `<meta name="build">`；
2. 额外生成一个 `build.json`（内容就是构建号）；
3. 页面启动时用 `cache: "no-store"` 取 `build.json`，跟自己的构建号比，
   不一样就带一次 `?t=<构建号>` 重载——URL 变了，HTML 就必须重新取，
   新 HTML 里指的就是新资源了。同一个版本只重载一次，不会来回死循环。

本地直接打开源码时构建号是 `dev`，不做这个检查。


推送时脚本会给 `styles.css` 和所有 js 的地址加一个版本参数，
例如 `js/map.js?v=muk7i4jf`：

```html
<link rel="stylesheet" href="styles.css?v=muk7i4jf" />
<script src="js/map.js?v=muk7i4jf"></script>
```

**这是为了解决"改了怎么没生效"的问题。** 浏览器会长期缓存 js 和 css，
部署新版本后用户看到的还是旧代码，表现就是"你说改了，但我这儿一点没变"。
地址里带上版本号之后，内容一变地址就变，缓存自动失效，
以后不用再反复提醒用户清缓存。

版本号是部署那一刻的时间戳，源文件本身保持干净（不带参数），
只有部署副本会加。

### 线上和本地完全一致

页面没有任何后端依赖，本地和线上跑的是同一套代码：

| | 本地 `node tools/serve.js` | 线上 GitHub Pages |
|---|---|---|
| 定位 | 可以（localhost 视为安全来源） | 可以（HTTPS） |
| 读取附近楼栋 | 可以 | 可以 |
| 语音播报 | 可以 | 可以 |

用本地服务启动只是为了拿到 `localhost` 这个安全来源，好让定位能用。
线上走 HTTPS，同样满足要求，所以功能上没有任何差别。

## 一次布局崩坏的复盘

「课表页最下面两个按钮总被挡住」「路线和课表页底部菜单跑到内容上方」——
这两个看起来不相干的毛病，**其实是同一个原因**，而且不在 CSS 里。

### 真正的原因：两个视图被写到了 `</html>` 后面

`index.html` 的末尾一度长这样：

```html
</body>
</html>

      <section class="view" data-view="route">
      ...
      <section class="view" data-view="course">
      ...
```

**浏览器会把 `</html>` 之后的内容甩到 `<body>` 末尾。**
于是这两个页面既不在 `.app` 里、也不在 `.views` 里，成了 body 的直接子元素，
还排在所有 `<script>` 后面：

```
body 的子元素: DIV.app, DIV.toasts, DIV.modal, 10个 SCRIPT, SECTION, SECTION
.views 的高度: 24px（只剩内边距）
route 的祖先链: SECTION.view < BODY < HTML
```

后果就是：`.app` 只有标题栏那么高，页面内容从三百多像素的空白后面才开始，
而固定定位的底部菜单在视觉上就"跑到内容上方"了。

### 为什么排查花了这么久

因为**标签数量是配平的**（58 个 `<div>` 对 58 个 `</div>`），
只数标签的检查完全发现不了问题。前几轮我一直在 CSS 上打转，
直到用无头 Edge 量了实际几何才定位到。

### 已经修好，并且加了防线

现在四个视图全部在 `<main>` 里，`</html>` 之后没有任何内容。
自检里新增了一组**结构完整性**检查，专门防这一类的错：

- `</html>` 之后不能有多余内容
- `html` / `body` 各只能有一个结束标签
- **四个视图区块必须都在 `<main>` 里面**（漏一个整页布局就塌）
- 导航栏必须在 `</main>` 之后、属于 `.app` 的末尾
- 样式表在 `<head>`、脚本在 `</main>` 之后
- 主要标签的开闭数量一致

### 顺带说：按钮位置

「确认导入」/「放弃这次识别」现在放在「从课表截图导入」标题下面、
其余内容之前。布局修好之后其实放哪儿都不会被挡了，
但放顶部更省事——不用翻到最后。

页尾留白仍然保留（脚本实测高度 + 渲染后自检，上限 480px）给其它页面兜底。

> 还踩过两个小坑：`.views` 的 `flex` 曾经写成 `1`（等于 `1 1 0%`），
> 基准尺寸为 0，内容一多就被挤住；`.app` 是 `min-height: 100vh` 的
> flex 容器时也有同样风险。现在 `.app` 是普通文档流。
