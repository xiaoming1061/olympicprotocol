# 到货第一天：从零到第一屏

按顺序做，每一步都写了「怎么算这步成功了」。**别跳过第 0 步**——先在电脑上
把数据这条路验通，板子上就只剩接线和烧录的问题了，不然屏幕上只有几个字符，
你分不清是配置错了还是线没插好。

整个过程大约 40 分钟，其中真正动手的大概 15 分钟。

---

## 第 0 步：在电脑上确认「课表能取到」（约 10 分钟）

这一步不碰板子。

**0.1 给手表设一条口令。** 手表走的入口需要一个独立口令，没配就是 404。

Cloudflare 控制台 → 你那台 Worker → **Settings → Variables and Secrets** →
Add → 类型选 **Secret**，名字填 `DEVICE_TOKEN`，值随手敲一串随机字符
（例如 `w7k2m9xq`）→ 保存后 **Deploy** 一次。

> 网页那条入口用的是另一个口令（`PROXY_TOKEN`），两个互不影响。

**0.2 在电脑上试一次。** 打开终端，跑：

```bash
node hardware/tools/check-endpoint.mjs https://<你的worker域名>/d/w7k2m9xq
```

它会问你学号和密码（密码输入时不显示，也不会进命令历史），然后帮你问一次接口。

**成功的标志**：打印出「下一节：…」和一张这几天的课表，最后写着「这条入口是通的」。
顺手核对一下：那张表里的课和时间，跟你课表上的一样吗？

**失败的话**，它会直接告诉你原因（密码错、上游超时、口令不对……），照提示改。

---

## 第 1 步：装 arduino-cli 和 ESP32 内核（一次性）

**你机器上这一步已经做完了**（arduino-cli 在 `%LOCALAPPDATA%\arduino-cli`，
ESP32 内核在 `D:\arduino-data`，两个库也装好了）。换一台电脑的话：

1. 下载 arduino-cli 的 Windows 64 位 zip，解压到任意目录；
2. 先把数据目录指到空间大的盘（C 盘最容易满）：

```powershell
$env:ARDUINO_DIRECTORIES_DATA = "D:\arduino-data"
$env:ARDUINO_DIRECTORIES_USER = "D:\arduino-user"
```

3. `arduino-cli core install esp32:esp32`（约 2GB）；
4. `arduino-cli lib install GxEPD2 ArduinoJson`。

> 为什么不用 PlatformIO：PIO 官方平台带的 Arduino 内核是 2.0.17，不支持 C6；
> pioarduino 的包又缺 PIO 要的清单文件。arduino-cli 是原生支持 C6 的。

---

## 第 2 步：填配置（约 5 分钟）

在仓库里进到 `hardware/firmware/`，把 `src/config.example.h` **复制**一份、
改名成 `config.h`（同一个目录），然后填四个值：

| 填什么 | 从哪来 |
| --- | --- |
| WiFi | 学校网填 `CUHK1x` 并把 `OP_WIFI_ENTERPRISE` 设为 `1`（用户名自动拼成 `学号@link.cuhk.edu.hk`，密码复用学校密码）；家用 WiFi 设为 `0` 再填名字密码。**必须是 2.4GHz** |
| `OP_DEVICE_ENDPOINT` | 第 0 步里那条完整地址 |
| `OP_SID` / `OP_PWD` | 你的学号和密码 |

> `config.h` 已经被排除在 Git 之外了——它带着密码，别提交、别发人。

用 VS Code 的 PlatformIO 打开 `hardware/firmware/` 这个目录（不是仓库根目录）。

---

## 第 3 步：接板子（约 5 分钟）

1. **先把电池插上**：电池那个白色小插头是 MX1.25，插进板子上标 `BAT` 的座子，
   注意别插反（插头有防呆，插不进就别硬来）。
2. **用能传数据的 Type-C 线**连电脑（有些线只供电，那种线烧录时会找不到串口）。
3. 第一次进下载模式：**按住板上的 BOOT 键不放，再插上 Type-C 线**，然后松手。

**成功的标志**：电脑的设备管理器里多出一个串口（VS Code 底部状态栏也会显示
PlatformIO 找到的端口号）。

> **注意按键别被外壳压住**：BOOT/PWR 被壳边卡住时，每次上电都会进下载模式——
> 表现是「屏幕不动、串口没日志、按键没反应」。合壳前用手指按几下，确认两个键
> 都能自己弹回来。

---

## 第 4 步：烧进去（约 2 分钟）

双击 **`hardware/tools/flash.cmd`**，按提示输入板子的串口（例如 `COM5`）。
它会依次做三件事：编译 → 烧录 → 打开串口日志。

也可以带参数直接跑：`hardware\tools\flash.cmd COM5`。

第一次编译约 2–3 分钟，之后再改就快了。

**烧录失败**：拔线，按住 BOOT 再插，重试一次；还不行就换根 Type-C 线。

---

## 第 5 步：看第一屏（1 分钟）

点 PlatformIO 底部的 **Monitor**（或者 `pio device monitor`）看串口日志，
同时盯着板子上的屏幕。屏幕会黑闪一下、然后出现内容。几种可能：

| 屏幕上 | 意思 | 怎么办 |
| --- | --- | --- |
| 画出课表，大字是下一节课的时间 | **成功** | 往下走第 6 步 |
| `NO WIFI` / `check config.h` | WiFi 名字或密码不对，或者用了 5GHz | 改 `config.h` 重新烧 |
| `NO DATA` + 一行英文 | 连上网了，但取数失败 | 那行字就是原因，对照 `hardware/firmware/README.md` 的排错表 |
| 白屏 / 花屏 / 只画一半 | 屏幕驱动型号对不上 | 改 `hardware/firmware/src/ui.cpp` 顶部的 `EPD_PANEL`，换成 `GxEPD2_154` 或 `GxEPD2_154_M09` 再烧一次 |
| 全黑、串口没输出 | 多半是线或下载模式的问题 | 回第 3 步 |
| 屏幕一直不动、串口能打开但一个字都不输出 | 芯片停在 ROM 下载模式（BOOT 被按住或卡住） | 松开 BOOT，拔线重插，别碰任何键 |

---

## 第 6 步：验三件事（约 10 分钟）

1. **页脚那个时间**：是不是和现在的时间对得上？对得上说明服务器时间校准成功了。
2. **大字那节课**：和你的课表对一下，是不是真的下一节课、时间和教室都对。
3. **电量**：把 USB 拔掉再看（插着 USB 时读的是充电电压，会显示 100%）。
   拔线之后按一下 PWR 键，应该会醒来刷新一屏。

这三件都对了，恭喜——硬件这条线就算通了。

---

## 第 7 步：接下来它自己会管自己

之后不用管它了：每天 07:00 刷一次，每节课前 15 分钟、开课和下课时各刷一次，
其余时间深度睡眠。**墨水屏断电后画面不消失**，所以它睡着的时候屏幕上也是有内容的。

想看看能撑多久：记下今天的电量和日期，过三四天再看一次电量百分比。
按设计每天醒 6 次左右，500mAh 电池大概能撑几个月。

**外壳先别急着装**——先用几天，确认刷新时机、电量显示这些都符合预期，
再决定要不要 3D 打印个支架当桌牌。屏幕排版想调的话，改 `src/ui_theme.h` 里的数字，
在电脑上跑 `node hardware/preview/render.mjs` 就能先看到效果，不用反复烧板子。
